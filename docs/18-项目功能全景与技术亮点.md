## 2. 核心技术实现（难点 → 设计 → 机制 → 结果）

### T01 AI 流式对话编排（`AiChatOrchestrator`，448 行）
- **难点**：LLM 整段返回慢且易超时；模型会编造文章名/数字（幻觉）；工具调用与流式输出交织、事件顺序容易错乱
- **设计决策**：不用"调完 API 返回 JSON"的套壳形态，自建**多阶段 SSE 事件协议**：`session → phase(understanding/searching/composing) → (tool)* → delta* → done|error`；phase 事件隐含上一阶段收尾（换阶段即收束，done/error 隐含 composing 收束），前端按序渲染
- **关键机制**：以 `stream=true` 调 OpenAI 兼容上游并**逐行解析 SSE data 帧**；`AiToolRegistry` 注册工具规格给模型，**工具轮**（completion → toolCalls → 执行 → 结果回填 → 再 completion）循环直至无 toolCalls；done 事件附带本轮命中文章 `{slug,title}`——**slug 来自工具结果而非模型生成**，从数据流层面杜绝编造；配额/用量经 `AiQuotaService` 落 Redis + 会话持久化
- **结果/踩坑**：首字延迟远低于整段返回；"后端开发分类有 2 篇文章"类幻觉在口径层根治

### T02 SSE 实时通知的连接治理（`NotificationController` / `NotificationAppService`）
- **难点**：SseEmitter 长连接泄漏；刷新页面打爆连接池；错误路径返回格式踩 500
- **关键机制**：心跳 20s 保活；**每用户连接上限 3 条、超限淘汰最旧**（注册表按用户组织）；429 后客户端有限退避（1s/2s/4s，最多 3 次）；SSE 错误路径也返回 JSON 错误壳（Accept 不强制 event-stream，R21）；登出/401 先 `close()` 再重连
- **结果**：连续刷新不丢推送、不刷屏——两类线上问题归零

### T03 幂等键三态机（资金安全，points 模块）
- **难点**：积分下单/调整重复提交=重复扣减；幂等键残留会把用户锁死无法重试；并发重放穿透
- **关键机制**：`Idempotency-Key`（作用域 = 操作人+接口+key），Redis 三态 **`PROCESSING(TTL 60s) → SUCCESS(TTL 24h) → 失败 DEL`**：写前 SETNX 占位挡并发重放，成功态防超时后重试，**失败必须 DEL**（踩坑：不释放=用户被锁死）；DB 层唯一约束兜底
- **配套**：余额变动全部走**条件更新** `SET x = x + ? WHERE version = ?`（R16，禁先读后写）+ 积分流水表（不可物理删除，审计依据）
- **结果**：重复点击零重复扣减、失败可安全重试

### T04 Redis 分布式锁：持有者校验的 Lua 释放（`OwnerAwareRedisLock`）
- **难点**：锁的误删（A 超时后释放了 B 持有的锁）
- **关键机制**：`SET key <uuid-token> NX PX <ttl>` 获取；**释放走 Lua 脚本比对 token 再删**（一次网络往返原子完成，41 行小而完备）；锁不重入（按场景短临界区设计）
- **结果**：跨实例互斥正确；与 T03 的条件更新配合构成并发正确性双保险

### T05 滑动窗口限流（`SlidingWindowRateLimiter`）
- **难点**：固定窗口在窗口边界有 2 倍突刺；限流要在公开接口上低成本复用
- **关键机制**：Redis **ZSET + Lua 脚本**（ZREMRANGEBYSCORE 清窗外 + ZADD + ZCARD 原子判定），**一次网络往返**完成限流判定；按接口+身份分 key
- **结果**：验证码/登录/留言等公开面统一限流底座，无边界突刺

### T06 认证与安全（`SecurityConfig` / `common/security`）
- **关键机制**：JWT 双 token（access 15m / refresh 14d）+ 刷新旋转；多设备会话表（超限折叠、过期自动滤除）；登录**算术验证码**（服务端 SVG 生成 + Redis 存储 + pepper 哈希防库泄露反推）；登出/踢出用 **Redis Token 状态位**而非黑名单扫描；密码 BCrypt + pepper
- **全局异常映射**（`GlobalExceptionHandler`）：BusinessException → 业务码、AccessDenied → 403、Authentication → 401、MethodArgumentNotValid/Bind/ConstraintViolation → `COMMON_VALIDATION_ERROR` + 字段级 errors、MaxUploadSize → 专属码、兜底 Exception → 500，全部收敛为统一响应壳 `{code,message,data,traceId}`
- **结果**：401/403 语义严格分离（F2 红线）、越权（IDOR）三查入测试

### T07 媒体安全管道（media 模块全链）
- **难点**：直传的安全边界；文件去重共享后的误删；缩略图派生对象的缓存与服务路由
- **关键机制**：
  1. **HMAC 预签名直传**：`PUT /media-upload/{token}`，token 内含业务/大小/哈希自校验 + TTL，绕过应用层大 body
  2. **sha256+size 去重**（限同上传者，避免"复用他人文件"误判）
  3. **删除前三路实时引用检查**（字段引用 + 正文内嵌 + 历史版本；被引用返回 `FILE_IN_USE` + 位置清单；`ref_count` 仅作快筛并有不一致告警）——去重共享让"直接删"必然误伤，这是该检查存在的理由
  4. **异步缩略图**：`FileActivatedEvent` 事务提交后（AFTER_COMMIT）触发，线程池 1–2 + 有界队列(64) + DiscardOldest；最长边可配（默认 320，生产 800）、JPEG q0.82、**EXIF Orientation 矩阵纠偏**、够小跳过、失败仅告警降级原图
  5. **派生对象服务路由**：缩略图无独立 files 行，`readForServe` 按 thumb_key 反查父文件、按父文件状态定可服务性，content-type 按真实编码标注（image/jpeg），`Cache-Control: immutable` 长缓存
- **结果**：首页图片首访字节 1.9MB→0.85MB（**-56%**）、单封面 583KB→12.6KB（**-97%**）、二次访问 0 网络传输；缩略图工具幂等可重跑

### T08 全链路 UTC 时间纪律（30 条红线中的 R1–R4）
- **难点**：多端时区差 8 小时；区间查询"最后一秒丢数据"
- **关键机制**：DB 全 UTC；前端唯一时间入口 `datetime.ts`（提交转 UTC、展示本地化）；**存储半开区间 `>= from AND < to`，界面闭合选 23:59:59 提交 +1s，投放期回显 -1s**；手工 SQL 先 `SET time_zone='+00:00'`；grep 红线禁硬编码 `+8/28800/INTERVAL 8 HOUR`
- **结果**：时区类 bug 归零，边界数据（59.900ms）可验证命中

### T09 游标分页与统计口径一致性
- **关键机制**：信息流不透明 Base64URL 游标（`(publishedAt,id)` 行构造器语义）替代 OFFSET 深翻页；置顶独立区块（上限 3）、主列表强制 `is_pinned=0`、**归档明细与计数同源排除置顶**、搜索有意不排除（口径显式化，R18）；LIKE 统一包含匹配并转义 `% _ \`
- **结果**：深翻页无抖动；"共 X 篇 vs 实际条数"类不一致被口径约束消灭

### T10 统一响应壳与错误码体系（`common/api` / `common/error`）
- **关键机制**：`{code,message,data,traceId}` 壳；错误码字符串化（`域_字段_原因` 命名）并登记 error-codes.md 契约；**Bean Validation 只做必填 + 10× 防爆硬上限，业务校验在领域层抛业务码**（R6：校验顺序错了会把业务码吞成校验失败——踩过的坑）；traceId 全链路透传
- **结果**：前端只按 code 分支不依赖 message（R8），错误可定位到字段

### T11 旧协议兼容层与渐进式迁移（wechat 模块）
- **关键机制**：13 条老协议挂 `/api/v1/legacy` 前缀，响应壳转换为旧语义（HTTP 200 + 数字 code + snake_case）；小程序按 **sceneId 长度分代际**（16 位=新码走 v1，32 位=老系统），新旧 PC 站的码都能扫；自有登录切换由配置位 `ownLoginUseV1` 一键切新
- **结果**：线上真实小程序零改造过渡、无停机

### T12 数据访问与库表设计（MyBatis + Flyway）
- **关键机制**：注解 + XML 混合，**批量投影行**（如 ArticleTagRow）一次 IN 查询回填列表关联数据（禁 N+1、禁 JOIN users 的跨域查询）；**软删默认过滤**且统计与列表口径必须同源（R13）；条件更新影响行数判定状态迁移（`WHERE status='TEMP'` 类）；Flyway 版本化迁移（历史脚本禁改，只增 V 脚本）；`uk_object` 唯一键定位 + `FOR UPDATE` 行锁用于状态机
- **结果**：32 张表演进零手工 DDL 事故；列表组装无 N+1（本机实测 10 条 18ms）

## 4. 简历素材

### 4.1 一句话项目描述
> 基于 **Java 21 / Spring Boot 3 / MyBatis / MySQL 8 / Redis** 的模块化单体后端（9 模块、139+ 接口、32 表），支撑 Vue3 门户 + 管理台 + 微信小程序三端在线上运行；涵盖 AI 流式对话编排（SSE + 工具调用）、幂等键资金安全、Redis 分布式锁与滑动窗口限流、SSE 连接治理、预签名媒体管道与缩略图服务、旧协议兼容层渐进迁移；**Testcontainers 集成测试 170 个全绿** + ArchUnit 架构守护 + 自研契约自动生成工具链。

### 4.2 展开 bullet（STAR，挑 3–5 条）

- **AI 流式对话编排**：自建多阶段 SSE 事件协议（session→phase→tool→delta→done），逐行解析上游 data 帧实现真流式；工具调用循环 + 结构化结果回填，从数据流层面根治模型幻觉；配额与会话全量持久化
- **资金安全幂等体系**：Idempotency-Key 三态机（PROCESSING 60s / SUCCESS 24h / 失败 DEL）+ Redis 分布式锁（SET NX PX + Lua 持有者比对释放）+ 乐观锁条件更新，重复提交零重复扣减、失败可重试不锁死
- **SSE 长连接治理**：20s 心跳、每用户上限 3 连接并淘汰最旧、429 有限退避、错误路径 JSON 化；解决"刷新丢推送"与"429 刷屏"两类线上问题
- **媒体安全管道**：HMAC 预签名直传、sha256 去重、删除前三路实时引用检查（防去重共享误删）、事务提交后异步缩略图（EXIF 纠偏 + 可配规格 + immutable 缓存 + 派生对象反查路由）；首页图片传输字节 **-56%**（单图 **-97%**）
- **工程化门禁**：Testcontainers 集成测试 **170 个全绿**、ArchUnit 把模块间依赖约束变成可执行测试、自研契约工具链自动生成 OpenAPI 与对接文档、全链路 UTC + 半开区间时间口径
- **渐进式迁移**：旧 Node 后端 13 条协议在新单体中建兼容层，小程序按 sceneId 分代际灰度，零停机切换

### 4.3 面试深挖预案（追问 → 关键答法）

| 追问 | 关键答法（本项目实际做法） |
| --- | --- |
| 幂等键为什么 Redis 而不是 DB 唯一索引？ | SETNX 占位 PROCESSING(60s) 挡并发重放，SUCCESS(24h) 防超时重试，失败 DEL 保证可重试（踩坑：不释放=锁死）；DB 唯一约束作兜底 |
| 分布式锁怎么防误删？ | value=实例随机 token，释放走 Lua 比对再删（原子）；TTL 兜底死锁；临界区短、不重入 |
| 限流为什么滑动窗口？ | ZSET+Lua 一次往返原子完成"清窗+计数+判定"，消除固定窗口边界 2 倍突刺；按接口+身份分 key |
| SSE 为什么不是 WebSocket？ | 单向推送场景够用、语义自带重连、代理友好；难点在连接治理（心跳/上限/淘汰/错误壳）而非传输选型 |
| AI 幻觉怎么治？ | 工具返回结构化事实（slug/计数），模型只做组织不做取证；done.articles 直接来自工具结果；prompt 层再加禁编造约束 |
| 缩略图为什么事务提交后异步？ | AFTER_COMMIT 不读未提交数据；生成失败不拖累上传（thumb_key NULL 降级原图）；有界线程池控资源；派生对象 immutable 可缓存 |
| 去重共享为什么危险？ | 同文件被多文章共享，直接删必然 404——删除前三路实时引用检查（字段/正文/历史版本），ref_count 仅快筛 |
| 深分页怎么优化？ | 不透明游标（publishedAt+id）替代 OFFSET；置顶/计数/明细口径显式化 |
| 时区怎么保证？ | 全链路 UTC、前端唯一转换入口、区间"存储半开/界面闭合"、grep 红线禁硬编码 +8 |
| 为什么单体分模块而不是微服务？ | 单人维护 + 流量规模下，分模块单体 + ArchUnit 边界 + app 层接口隔离，获得模块化收益且无分布式开销；迁移已按模块预留拆分线 |
