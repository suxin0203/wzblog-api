## 1. 计划假设

1. **单人 + 多 Agent**：1 名负责人裁决契约与合并；M0~M8 各由一个模块 Agent 在独立 worktree 推进，审查 Agent 只出结论。
2. **业余投入 2~3 h/天**：有效工时按 2.5 h/天折算，周末与整块时间用于并发/安全用例和联调。
3. **日历周期 = 有效工作日 × 2~3**：v2 §10 的“天”是有效工作日，不是自然日；计划只承诺顺序与出口条件，不承诺日期。
4. **P0/P1/P2 可砍**：P0 35 项为底线；P1 默认完成；P2（AI/微信/扫码/RAG/评论点赞）可按 05 §7 顺序砍，砍后不删表与路由。
5. **文档先行**：每个模块开工前其文档必须定稿（路由/DTO/错误码/用例冻结）；未定稿不开工，契约变更先改 00 再改代码。

## 7. 质量门禁、缓冲与砍单

**质量门禁（合并前全过）**
1. `mvn -q clean verify` 绿；`domain`/`app` 行覆盖 ≥70%，无空断言与跳过用例。
2. ArchUnit 通过：api 不依赖 infra、无跨模块 Mapper、`common` 不反向依赖模块。
3. Flyway 空库可迁移、seed 可重复导入、已执行脚本未改动。
4. 路由/DTO/枚举/错误码与 00/03/04 逐字一致；OpenAPI 无未登记接口。
5. 401/403/越权/ADMIN 绕过/归属校验用例全部通过。
6. 并发与幂等实测：并发刷新、下单、库存、计数、消息重复消费。
7. 列表/统计 SQL 附 EXPLAIN，无全表扫描与大表 filesort；慢 SQL 阈值 200ms。
8. 无密钥/Token/本地配置入库；traceId 贯穿；日志不含敏感字段。

**风险缓冲（4 条）**
1. 外部依赖（智谱/微信）未实测：时间盒 2 天，先 Mock 与开关降级，超时按 05 §7 顺序砍。
2. 积分并发/状态机返工：阶段 4 后预留 15%（约 20 人时）返工缓冲。
3. 文档评审阻塞：每模块评审 ≤1 天，超时按文档默认值冻结并登记。
4. 环境与 CI 不稳：阶段 0 固化镜像与脚本，预留 8 人时排障。

**砍单顺序（引用 05 §7）**：RAG → 扫码 → 微信登录/绑定 → AI 摘要/标签 → AI 对话 → 通知（先 SSE 后整块）→ 看板（先 overview 后整块）→ 修订历史。每次只砍一项并登记；P0 与并发/安全用例不可砍。

**砍单登记**：
1. RAG（2026-10-26）：P2 可选，默认关闭，未实现（契约保留）。
2. 扫码登录（2026-10-26）：P2 可选，随 M8 一并砍除。
3. **M8 微信登录/绑定（2026-10-26 砍除 → 同日恢复）**：砍除理由为无真实凭据无法验收；同日用户取得真实小程序 AppID/Secret 并要求兼容已上线小程序，按 [13-微信扫码复原计划](13-微信扫码复原计划.md)（v2，已按小程序与 Node 源码校准）恢复开发。
