## 1. 质量目标与通过判定

### 1.1 五类质量目标

| 目标 | 具体含义 | 主要验证手段 | 典型不通过表现 |
|---|---|---|---|
| 正确性 | 路由、响应壳、错误码、状态机、权限、分页、时间与 ID 序列化与契约一致 | 模块验收用例 + Web 切片 + 契约比对 | 返回未登记错误码；BIGINT 输出为数字；状态机越级 |
| 并发安全 | 刷新、点赞、下单、库存、引用计数、扫码确认在并发下不重复、不超卖、不丢更新 | 并发测试 + 数据库最终态断言 | 库存为负；同一幂等键产生两笔流水；刷新产生多个 family |
| 安全 | 认证、授权、输入、上传、日志、依赖无已知高危缺陷 | 安全清单 + 定向攻击样本 | 改他人资源成功；脚本未清洗；token 进日志 |
| 性能 | 达到 v2 §8.1 的目标，且查询计划可解释 | k6 + EXPLAIN + 慢 SQL 扫描 | 目标超限且无索引或改写方案 |
| 可回归 | 每个缺陷修复都有可重复执行的回归用例，历史行为不被破坏 | CI 全量 + 缺陷闭环 | 修复未补测试；同类问题二次出现 |

### 1.2 覆盖率的定位

- 覆盖率是**下限约束**，不是验收目标。按 v2 §8.4：`domain` 与 `app` 行覆盖不低于 70%，`infra` 以集成测试覆盖关键路径。
- 禁止用无断言的“走过场”测试、只为提升行数的 getter/setter 测试凑数；覆盖率上升不能替代 07a 用例通过。
- 新增或修改的分支至少覆盖受影响的状态码：200/201、400、401、403、404、409、422、429；涉及 SSE 时另测中断与超时。

### 1.3 门禁分级

| 级别 | 适用范围 | 处理 |
|---|---|---|
| 阻断 | 编译失败；P0/P1 用例失败；ArchUnit 失败；迁移不可从空库执行；契约破坏；高危漏洞；密钥泄露 | 禁止合并、禁止发布 |
| 告警 | P2 用例失败；性能接近目标但未超限；非核心日志缺失；覆盖率低于建议值但高于下限；环境差异与已知限制 | 记录风险，版本负责人确认后可发布 |

## 2. 测试分层与工具

| 层 | 范围 | 工具 | 运行时机 | 失败处理 |
|---|---|---|---|---|
| L1 单元 | 领域规则：状态机、阅读时长、日上限、slug、敏感词、游标编解码、积分计算、权限判定 | JUnit 5 + AssertJ + Mockito | 每次提交 / PR | 阻断；禁止重试掩盖 |
| L2 Web 切片 | 参数校验、错误码映射、鉴权注解、响应壳、BIGINT 字符串、traceId、内容协商 | `@WebMvcTest` + MockMvc | 每次 PR | 阻断；补对应 400/401/403/404/409 分支 |
| L3 集成 | 真实 MySQL/Redis/MinIO、Flyway 空库、事务、事件、缓存、对象存储、管理端聚合 | `@SpringBootTest` + Testcontainers | PR 合并队列、main、发布前 | 阻断；保留容器日志与 traceId |
| L4 并发 | 刷新、点赞、下单、库存、引用计数、扫码确认、SSE 连接 | JUnit + `CountDownLatch` / `ExecutorService` | 合并队列、main、发布前 | P0 场景阻断；记录线程数与最终态 |
| L5 架构 | 分层依赖、模块隔离、`shared` 不依赖 `modules`、命名与包结构 | ArchUnit | 每次 PR | 阻断；不允许“先合后补” |
| L6 契约 | 路由、权限、请求/响应字段、错误码、OpenAPI 生成物 | springdoc + OpenAPI 比对 | 每次 PR | 破坏性变更阻断；新增字段需登记 |
| L7 安全 | XSS 样本、越权、Mass Assignment、上传伪装、JWT 攻击、日志脱敏 | 定向用例 + 依赖扫描 | PR（高危项）、发布前全量 | 高危阻断；中危限期修复 |
| L8 性能 | 读多写少、下单热点、AI SSE 并发、缓存失效；EXPLAIN 与慢 SQL | k6 + MySQL EXPLAIN + Micrometer | 发布前、每周基线、重大查询变更 | 未达 v2 §8.1 阻断发布，除非书面例外 |

### 2.1 分层边界

- L1 不启动 Spring，不连数据库；规则必须可在毫秒级重复执行。
- L2 只加载 Web 层与必要 Mock，不连真实中间件；用于验证“接口表面契约”，不替代 L3。
- L3 从空库执行 Flyway，禁止 `ddl-auto`；同一测试类共享容器，跨类按第 3 节隔离。
- L4 必须断言数据库最终态（行数、余额、库存、计数），不能只断言 HTTP 状态码。
- L5 规则与 02 §4 的分层一致：`api → app → domain`、`infra → domain`，`api` 不得依赖 `infra`。
- L6 以 00 §4/§5 与各模块错误码表为基线；`04-接口契约.md` 产出后，以其为唯一比对源。
- L7 与 L4 可复用同一套容器，但安全样本必须独立断言“未被利用”，不能只看返回 200。
- L8 使用与 CI 隔离的固定环境；压测数据由脚本生成，不复用 `V2__seed.sql`。

### 2.2 失败处理统一规则

- 断言失败一律视为真实失败；仅基础设施抖动允许**一次**重试，且需在报告中标注重试原因。
- 被隔离（quarantine）的用例必须有缺陷编号与恢复期限，不允许静默 `@Disabled` 长期存在。
- 测试日志必须带 `traceId`；集成失败时归档容器日志、SQL、Redis key 快照与 MinIO 对象清单。

## 3. 测试环境与数据

### 3.1 环境形态

| 环境 | 组成 | 用途 | 数据 |
|---|---|---|---|
| 本地单元 | 无容器 | L1/L2 快速反馈 | 内存构造 |
| CI 集成 | Testcontainers：MySQL 8.0、Redis 7、MinIO；镜像与 08 §3.1 对齐 | L3/L4/L5/L6/L7 | Flyway 空库 + 固定种子 |
| 本地全栈 | `docker compose` 的 mysql/redis/minio/app | 联调、演示、手工验收 | 种子 + 演示数据 |
| 性能环境 | 单实例 app + 独立 MySQL/Redis/MinIO，资源按 08 §13 推荐 | L8 | 脚本生成的大数据集 |

- Testcontainers 在同一 JVM 内复用容器（singleton），跨 CI job 不复用；本地开启 reuse 以缩短启动时间；集成测试 profile 使用 `application-test.yml`：动态端口、`spring.flyway.clean-disabled=false`。
- MinIO 使用独立测试桶，桶名带运行标识；对象 key 仍由服务端生成，测试不得自行拼 key 写入。

### 3.2 数据库与种子

- 每个集成测试套件从空库执行 `V1__schema.sql`，再执行 `V2__seed.sql`；禁止手工建表或依赖开发库残留。
- 固定种子提供：管理员/编辑/普通用户各至少一个、基础分类与标签、站点配置、可售商品与称号；密码与 token 使用测试专用值。
- 用例自建数据统一加运行前缀（用户名、邮箱、slug、标题），断言不依赖自增 ID 的具体数值；JSON 中的 ID 一律按字符串处理。
- 财务、订单、引用计数类用例通过“本次创建的用户/商品/文件”过滤，禁止对全表做无范围断言；大数据集（第 6.2 节）只用于性能与 EXPLAIN，不写入种子。

### 3.3 隔离策略

| 测试类型 | 隔离方式 | 清理 |
|---|---|---|
| L1/L2 | 无共享状态 | 不需要 |
| 同步数据库集成 | 测试方法事务回滚 | 回滚即可 |
| 异步事件/SSE/锁/并发 | 不用事务回滚（会被提交或跨线程） | 按运行前缀删除业务行，按 key 前缀清理 Redis，按桶前缀清理 MinIO |
| 管理端聚合 | 独立日期区间与独立用户 | 删除该区间 `daily_stats`/`article_daily_stats` 测试行 |
| 性能 | 独立库与独立桶 | 压测前重建，压测后保留报告 |

- 集成测试默认串行执行；L1 可并行。任何用例不得依赖执行顺序或其他用例的残留数据。
- Redis 使用独立 database index，key 统一 `wzblog:{module}:{biz}:{id}`；限流、锁、缓存、会话使用不同前缀，测试按 `wzblog:` 前缀 `SCAN` + `UNLINK`，禁止对共享实例执行 `FLUSHALL`。
- SSE 未读计数按用户清理；MinIO 测试桶按运行标识隔离并只授予测试账号最小权限；MySQL 测试账号只授权测试库。

### 3.4 时间与业务日

- JVM 固定 UTC（Surefire `-Duser.timezone=UTC`），数据库会话时区 UTC；API 输出 ISO-8601 `Z`。
- 业务日按 `Asia/Shanghai` 计算；时间通过可注入的 `Clock` 获取，禁止在业务代码与测试中裸调系统时间。
- 边界样本固定为 `15:59:59Z` 与 `16:00:00Z`（对应上海 23:59:59 与次日 00:00:00），覆盖登录积分、发布/评论日上限、阅读去重、订单号日期段、看板日界。
- 过期类场景用“回填历史时间”造数（如 25 小时前的 TEMP、7 天前的 ORPHAN），不用真实等待；TTL 断言用区间而非精确秒数。

## 4. 关键专项策略

> 本节只写方法与判据，逐条用例编号与步骤由 07a 展开。所有专项都必须同时覆盖“正常路径、边界、失败路径、并发路径”。

### 4.1 认证并发刷新、复用检测与锁定

- **并发刷新**：同一 refresh token、同一 UA，用屏障同时发起 20 个请求；收集全部响应后断言：仅 1 条新 `refresh_tokens` 行、`replaced_by_id` 指向该行，其余请求在 10 秒宽限内返回同一 Token 对，family 未被吊销。
- **复用检测**：宽限期后换不同 UA 重放旧 token，断言 401 `AUTH_REFRESH_REUSED`，该 family 全部 `revoked_at` 非空；再断言新 token 也不可用。
- **锁定与验证码**：连续 5 次错误密码后第 6 次正确密码仍被拒，断言 429 `AUTH_ACCOUNT_LOCKED`、`Retry-After` 约 900 秒、审计含 BAD_CREDENTIALS/LOCKED；验证码错 3 次后删除，再提交返回 `AUTH_CAPTCHA_EXPIRED`。
- **登出与停用**：登出后旧 access 因 `jti` 黑名单立即 401；停用账号持有效 access/refresh 访问返回 403 `AUTH_ACCOUNT_DISABLED`，refresh 同时被吊销。
- **防抖动**：用注入时钟控制宽限与过期，UA 按场景固定，断言数据库最终态而非响应顺序；不真实等待 15 分钟，用回填 Redis TTL/审计时间验证。

### 4.2 Markdown XSS 样本与清洗回归

- 样本库按攻击面分组：原始 HTML 标签、事件属性（`onerror`/`onload`）、危险协议（`javascript:`、`vbscript:`、`data:text/html`、`data:image/svg+xml`）、大小写与实体编码绕过、零宽字符与空白变体、畸形标签、Markdown 链接/图片注入、HTML 注释绕过。
- 断言输出白名单：仅允许契约列出的标签与属性；`href` 仅 http/https/mailto；`img.src` 仅本站对象存储路径；外链带 `rel="noopener noreferrer"`；无脚本、无内联事件、无 `iframe/object/embed`。
- 做**幂等回归**：同一内容保存两次、读取两次、从修订回滚一次，清洗结果一致；TOC 锚点在清洗后仍存在且与 HTML `id` 一致；样本库随缺陷增长，每发现绕过样本先入库再修复，清洗器升级时全量重跑。
- 评论、留言、昵称等纯文本字段单独验证“输出转义”，不能只依赖 Markdown 清洗。
- 大文档边界按 v2 §7.2 验收：正文 200 KB 上限、1 万字渲染 < 300ms；超限返回 400 并定位到 `contentMd` 字段。

### 4.3 点赞计数对账

- **并发 toggle**：同一用户同一文章 100 并发点赞，断言仅 1 条明细、`like_count` 仅 +1；重复提交 10 次仍幂等；唯一键冲突被捕获后不得产生 500。
- **状态一致性**：随机 toggle 序列后，断言 `articles.like_count` 等于该文章 LIKE 明细行数；取消到 0 后不为负；事件仅在实际状态变化时发布；评论点赞按 `comments.like_count` 同口径验证。
- **对账**：人工把计数改大/改小，执行对账任务，断言计数回正、`audit_logs` 记录原值与新值、偏差被量化；同日重跑不重复修复；不以 Redis 展示计数作为真相。

### 4.4 积分账本幂等、日上限、库存与状态机

- **幂等**：同一 `Idempotency-Key` 同请求体提交 10 次，断言 1 个 201 + 9 个 200、同一 `orderNo`、1 条 `REDEEM`、只扣 1 次；同 key 不同请求体返回 409 `COMMON_IDEMPOTENCY_CONFLICT`。
- **日上限**：在业务日边界前后分别造“已发 9 篇/10 条评论”的数据，批量投递事件，断言只补到上限、`grantedAmount=0` 的记录不写流水；并发投递时上限不被突破。
- **库存**：`stock=1` 时 50 并发下单，断言仅 1 成功、`stock=0`、`sold_count=1`、无负库存；`stock=NULL` 时并发全部成功且库存仍为 NULL；禁止“先查后写”。
- **状态机与锁序**：遍历合法/非法迁移，非法迁移返回 409 `ORDER_STATE_INVALID` 且日志与余额不变；取消/驳回只退一次积分、只回补一次库存；称号订单在 APPROVED 授予且重复审批被拒；创建与取消并发无死锁，锁序固定为商品 → 账户 → 流水/订单。
- **账本真相**：每个场景结束后断言 `balance = SUM(ledger.amount)`；对账差异修复本身追加 `ADMIN_ADJUST` 流水，并写审计。

### 4.5 文件魔数、像素炸弹与引用计数

- **类型伪装**：zip/PHP/EXE 改名为 `.png`、`.svg` 改名 `.png`、GIF89a，均返回 400 `FILE_TYPE_UNSUPPORTED`，对象被删、行置 DELETED；`Content-Type` 伪造不改变结论。
- **资源上限**：10 MB 图片返回 `FILE_SIZE_EXCEEDED`；20000×20000 返回 `FILE_PIXEL_EXCEEDED`，进程不 OOM、堆在断言后回落；8000×8000 边界单独验证。
- **SSRF/路径**：presign 请求体额外携带 `objectKey`、`bucket`、路径穿越串，断言额外字段被忽略或 400，实际 key 仍由服务端生成并匹配正则。
- **引用计数**：两个并发事务各 claim 同一 key，断言 `ref_count=2` 无丢失更新；文章保存做新旧 key 差集，删除图片后对应 key 归零、保留图片不变；封面替换旧 key release、新 key claim。
- **清理**：先 dryRun 再真实清理，断言 dryRun 不改库与对象；TEMP 超 24 小时、ORPHAN 超 7 天被清理，在用文件与对象保留；删除文章后 7 天内图片仍可访问。
- **去重与确认**：同图两次上传只保留一份对象；重复 confirm 幂等；未 PUT 直接 confirm 返回 `FILE_OBJECT_MISSING`；超时 confirm 返回 `FILE_CONFIRM_TIMEOUT`；缩略图验证方向修正、最长边 320、`thumb_key` 规范、EXIF 不进入缩略图，异步失败可重试且不阻塞 confirm。

### 4.6 AI SSE 顺序、断开取消、工具轮次、配额与注入

- 使用本地 Mock 上游控制增量、工具调用、429 与超时；记录上游请求次数与取消信号，CI 不调用真实模型。
- **事件顺序**：`session → tool(start) → tool(end) → delta* → done`，`done` 只出现一次，`done` 后不得再有 `delta`；响应头含 `X-Accel-Buffering: no`；20 秒无增量时至少收到一次 `: ping`。
- **断开取消**：客户端 3 秒后断开，断言 1 秒内上游请求被取消、消息落库 `INTERRUPTED` 且保留已生成片段、不再产生计费调用。
- **工具轮次**：最多 2 轮；第 3 轮请求工具时不再调用，`done.finishReason=tool_limit`；工具结果截断 6000 字符；工具异常转为可读结果，对话不中断；工具单次 10 秒、总超时 60 秒。
- **配额**：按 00 §7 的 IP 10 次/分、用户 100 次/天、游客 IP 50 次/天验证；超限 429 `AI_QUOTA_EXCEEDED` 且带 `Retry-After`；配额检查在调用上游之前，超限不产生 token 消耗。
- **注入**：使用“忽略规则/输出表结构/列出用户邮箱”等样本，断言回答与工具参数均无表名、SQL、邮箱、openid；工具白名单只暴露公开字段，用户输入不拼接进工具参数。
- **失败语义与防抖动**：未开始流式时上游 429 返回 502 `AI_UPSTREAM_ERROR`；已开始流式则发 `error` 事件且 HTTP 保持 200；`ai.enabled=false` 返回 503 `AI_DISABLED`；游客令牌缺失/错配/过期按 M6 契约断言 401/403/410；顺序断言用事件序号而非绝对时间，Mock 延迟固定，并发测试限制每 IP 3 条连接并区分 429 与正常完成。

### 4.7 缓存一致性、雪崩与 Redis 降级

- **一致性**：文章更新后 `version+1`，新 key 立即读到新值、旧 key 自然过期；分类/标签/公开配置更新后，读路径与广播失效监听均能看到新值；不允许依赖“删除成功”保证一致。
- **击穿/雪崩**：热点 key 失效后 1000 并发读，断言回源 1 次、其余等待后返回、无 500，单飞锁未抢到者不得重复回源；TTL 必须有 ±10% 抖动，禁止批量同一秒过期；空结果缓存 60 秒防穿透。
- **降级与边界**：停止 Redis 或断开连接后，读接口按模块文档降级读库且不返回 500，安全敏感路径若文档要求失败关闭则断言拒绝而非静默放行；余额、库存、订单状态不缓存，计数可缓存展示但写路径以数据库为准，缓存异常不得回滚已提交事务。

## 5. 安全测试清单

| # | 风险 | 测试方法 | 通过判据 |
|---|---|---|---|
| 1 | Mass Assignment | 在 `PUT /users/me`、管理端用户/商品/订单请求中注入 `role`、`status`、`balance`、`points`、`ownerId` 等字段 | 响应 200 或 400，但数据库字段不变；仅 DTO 白名单字段生效 |

| 3 | SQL 注入 | 搜索关键词、登录用户名、后台筛选、排序参数注入单引号、注释、时间盲注 payload | 参数化生效；无 SQL 错误回显；排序仅接受白名单；响应时间无异常放大 |
| 4 | XSS | 文章正文使用 4.2 样本；评论/留言/昵称/公告/友链输出脚本与事件属性 | 正文按白名单清洗；纯文本字段转义；无脚本执行上下文 |
| 5 | SSRF | presign 注入任意 key/bucket/内网 URL；检查是否存在 URL 抓取入口 | 无 URL 抓取能力；对象 key 服务端生成；内网地址不可达 |
| 6 | 上传 | 改扩展名、伪造 Content-Type、SVG/GIF、超大文件、超大像素、路径穿越 | 按魔数 + 解码 + 大小/像素拒绝；无对象残留；无路径穿越 |
| 7 | CORS | 使用非白名单 Origin 发起简单请求与预检；检查 `*` 与凭证组合 | 不返回允许头；白名单来源正常；预检缓存符合配置 |
| 8 | Actuator | 匿名访问 `/actuator/health`、`/info`、`/prometheus`、`/env`、`/heapdump` | 仅 health/info 公开；prometheus 需 ADMIN 或内网；其余 401/404 |
| 9 | JWT 攻击 | 伪造签名、`alg=none`、HS/RS 混淆、过期、错误 `iss/aud`、登出后重放、停用用户重放 | 全部 401 或 403；黑名单立即生效；不泄露密钥或堆栈 |
| 10 | 敏感日志 | 抓取登录、刷新、上传、扫码、AI 全流程日志与错误响应 | 无密码、token、openid、session_key、bindToken、ticket、签名 URL 全文；traceId 可关联 |

| 12 | 供应链与密钥 | 依赖扫描、镜像扫描、仓库与镜像层检查 `.env`/密钥；弱 `JWT_SECRET` 启动 | 无高危依赖；无密钥入库/入镜像；密钥长度不足启动失败 |

## 6. 性能测试

### 6.1 目标基线（引用 v2 §8.1）

| 接口 | 目标（本机/单实例） | 说明 |
|---|---|---|
| 文章详情（缓存命中） | P95 < 50ms | 不含网络 |
| 文章列表 / 搜索 | P95 < 200ms | 20 万行测试数据 |
| 登录 | P95 < 400ms | BCrypt 强度 10 是主要成本 |
| 点赞/收藏 | P95 < 80ms | 单事务两三条 SQL |
| 下单 | P95 < 150ms | 行锁竞争下允许更高 |
| 看板 | P95 < 300ms | 预聚合 + 缓存 |
| AI 首 token | 记录基线，不承诺绝对值 | 取决于上游模型 |

- 上表是发布门禁的唯一性能目标来源；模块文档中的更细指标用于定位瓶颈，不作为替代目标；测量必须注明机器、容器资源、数据规模、脚本版本与运行时长，不得混用不同环境的数字。

### 6.2 数据规模（建议值）

| 表 | 建议规模 | 用途 |
|---|---|---|
| `users` | 10 万 | 登录、用户趋势、后台列表 |
| `articles` | 20 万 | 信息流、搜索、归档、详情缓存 |
| `comments` | 50 万 | 评论树、审核列表、计数对账 |
| `points_ledger` | 100 万 | 流水查询、日上限、对账、看板积分 |
| `article_reactions` | 100 万 | 点赞/收藏列表与计数 |

> 以上为建议值，用于压测与 EXPLAIN，不是数据库契约；可按机器能力等比缩减，但必须在报告中注明实际规模。

### 6.3 k6 场景

| 场景 | 目标 | 关键断言 |
|---|---|---|
| 读多写少 | 信息流翻页、文章详情、搜索、分类/标签页混合；验证缓存命中与游标翻页 | 各接口 P95 对照 6.1；翻 100 页耗时不随页码增长；无 5xx；缓存命中率与回源次数可解释 |
| 下单热点 | 限量商品并发下单、同 key 重试、余额不足、取消并发 | 不超卖；库存/已售/流水/余额一致；成功与 422/409 比例可解释；下单 P95 对照 6.1 |
| AI SSE 并发 | 多路 SSE 同时建立、持续增量、部分客户端中途断开；Mock 上游 | 首 token 记录基线；连接数上限生效（IP 3、全局 200）；断开 1 秒内取消；无泄漏连接与重复落库 |
| 缓存失效 | 热点文章高频更新 + 高并发读；批量 key 同时过期 | 更新后立即可见；单 key 失效只回源 1 次；无雪崩式 5xx；P95 对照 6.1 |

- 并发梯度由基线试跑确定并在报告中记录；每档至少稳定运行到统计有效，禁止只跑数秒就下结论；压测脚本与报告一起归档，AI 场景必须使用 Mock 上游。

### 6.4 EXPLAIN 与慢 SQL

- 所有列表、搜索、统计、对账查询在建议数据规模上执行 `EXPLAIN`（必要时 `EXPLAIN ANALYZE`），记录 `type/key/rows/Extra`。
- 判定：不得出现大表 `type=ALL`；不得出现大表 `Using filesort`/`Using temporary`；游标分页不得退化为 `OFFSET` 深翻页；搜索应命中全文索引，降级 `LIKE` 仅在关键词过短时发生。
- 以 v2 §8.3 的 200ms 为慢 SQL 阈值，扫描 MyBatis 拦截器日志；新增或变更查询若出现慢 SQL，必须在 PR 中附计划与改写方案。
- 看板与对账允许离线聚合，但单语句需有超时与分批策略；不得在首屏做多表全量聚合。

## 7. CI 门禁

### 7.1 流水线

1. checkout + JDK 21 + Maven 缓存。
2. 编译（含注解处理器与 MapStruct/Lombok 顺序）。
3. 单元测试与 Web 切片（Surefire）。
4. 集成测试（Failsafe + Testcontainers，Flyway 从空库）。
5. ArchUnit 架构测试。
6. springdoc 生成 OpenAPI 并归档，与基线做差异比对。
7. 依赖与镜像安全扫描（高危阻断）。
8. 构建镜像（PR 只构建不推送；main/tag 推送并记录 digest），归档测试与扫描报告。

### 7.2 PR 阻断条件

- 编译失败，或任一 P0/P1 用例失败，或集成测试因环境外原因无法执行。
- ArchUnit 失败：`api` 依赖 `infra`、模块越界、`shared` 依赖 `modules`。
- Flyway 无法从空库执行，或修改了已执行的历史迁移文件（checksum 不一致）。
- OpenAPI 破坏性变更：删除/改名路由、改变权限标记、删除错误码、改变必填字段或类型。
- 新增/修改查询未附 EXPLAIN，或计划出现全表扫描/大表 filesort。
- 缺陷修复未带回归测试；新增分支未覆盖对应 400/401/403/404/409。
- `domain`/`app` 覆盖率低于 70% 下限（覆盖率达标不替代用例通过）。
- 高危依赖漏洞、密钥/凭证入库、镜像以 root 运行且无说明。
- 契约与实现不一致：未登记错误码、BIGINT 以数字输出、响应壳缺 `traceId`。

### 7.3 报告归档

- 归档 Surefire/Failsafe XML 与 HTML、JaCoCo（如启用）、ArchUnit 结果、OpenAPI 文件、依赖与镜像扫描报告、失败容器日志。
- 性能报告归档 k6 摘要与原始指标，命名含 commit、场景、数据规模；发布报告随 tag 长期保存，PR 报告至少覆盖最近一次发布回溯。

## 8. 缺陷管理

### 8.1 严重级别

| 级别 | 定义 | 示例 | 处理要求 |
|---|---|---|---|
| S1 阻断 | 数据损坏/丢失、资金或积分错误、越权、密钥泄露、核心路径不可用 | 超卖；余额与流水不一致；USER 改他人文章；token 进日志 | 立即修复，阻断合并与发布 |
| S2 严重 | 主要功能错误、并发结果不一致、无绕行方案 | 刷新产生多 family；评论树错层；SSE 断开后仍计费 | 阻断发布，合并前修复 |
| S3 一般 | 边界错误、提示或错误码不当、有绕行方案 | 分页边界少一条；错误文案不符；限流阈值偏差 | 可随版本发布，登记修复计划 |
| S4 轻微 | 文档、日志格式、非功能展示问题 | 注释错别字；指标标签不规范 | 批量处理，不阻断 |

### 8.2 复现模板

- 标题与编号：模块 + 现象 + 影响。
- 环境与前置：commit、镜像 tag、Compose profile、数据规模、时区；用户角色、资源归属、开关配置、Redis/DB 初始状态。
- 步骤与结果：请求方法 + 路径 + 关键参数 + 并发数/顺序；实际/期望的状态码、`code`、关键字段、数据库最终态。
- 证据与影响：必现/偶现、`traceId`、日志片段、SQL 结果、对象清单；受影响范围、关联用例编号、初步定位。

### 8.3 回归与修复验证

- S1/S2 修复必须新增自动化回归用例，优先落在能稳定复现的最低层（L1 规则、L3 集成、L4 并发）。
- 验证顺序：回归用例在修复前失败、修复后通过；再跑受影响模块全量、跨模块事件链路、全量集成；涉及查询时重跑 EXPLAIN 与性能场景，涉及鉴权时重跑 401/403/IDOR 用例。
- 关闭条件：用例入库、CI 全绿、报告注明验证环境与版本；同类问题再次出现时重新打开并升级级别。

5. **演示脚本**：按 08 §12 从零执行 12 步，记录每步响应与截图；演示数据与报告版本一致。

- [ ] CI 全绿：编译、单元、集成、ArchUnit、OpenAPI、安全扫描。
