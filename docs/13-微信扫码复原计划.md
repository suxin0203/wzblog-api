## 1. 关键架构决策：旧协议皮肤 + 新安全内核

**兼容层不是"再写一套登录系统"，而是把 Java 的认证体系包进旧协议的壳里：**

- 兼容端点签发的就是 **Java 的双 Token**（accessToken 15min / refreshToken 家族轮换）——小程序拿它当 Bearer 用，Java 的 `JwtAuthenticationFilter` 天然识别，后续调 Java 任何新契约接口都通。
- 壳完全按旧格式：数字 code、token 在顶层、user 对象 **snake_case 旧字段**（`avatar_url`、`created_at`…）、HTTP 语义按 request.js 的判定习惯（业务错误 200、/me 鉴权失败 401）。
- 与 Node 的唯一可感知差异：token 有效期 15min vs 2h——**小程序无感**（request.js 本来就有 401→refreshToken 刷新队列），且更安全。
- `/users/refresh` 兼容端点内部走 Java 刷新（含轮换/复用检测），壳按旧的 `{code:200, token, data}` 返回。

## 2. 兼容端点清单（权威规格，全部源码核实）

### 2.1 identity 域（放 `modules/identity/api/compat/`）

| 旧路径 | 方法 | 行为要点（Java 实现） |
|---|---|---|
| `/wechat/openid/{code}` | GET | 代理 `jscode2session`；成功返回 **无 code 字段**的 `{message, data:{openid,...}}`（request.js"格式3"分支）；失败 `{code:0, errcode, errmsg}`。session_key 不外发（比 Node 收紧，小程序不读它） |
| `/wechat/userinfo/{openid}` | GET | openid 已绑定→登录并发 token：`{code:200, token, data:{user(snake_case), refresh_token}}`（10h→Java 15min，data 里带 refresh_token 供小程序 401 刷新）；未绑定 `{code:0, message:'用户不存在'}` |
| `/users/captcha` | GET | 算术验证码 `{captchaId, num1, num2}`，答案=num1+num2，Redis 5min，提交 **MD5**（复用 M1 CaptchaStore 加算术变体） |
| `/users/register` | POST | `{username, password(Base64), email, openid?, captchaId, captchaAnswer(MD5)}` → 复用 M1 注册；**善意修复：openid 一并绑定**（Node 忽略了该字段，属旧版缺陷；修复后注册即可登录，不破坏任何协议） |
| `/users/login` | POST | `{username, password(Base64), captchaId, captchaAnswer(MD5), openid?}` → 复用 M1 登录（映射验证码差异）；传 openid 则绑定（同 Node）；响应 `{code:200, token, refreshToken, data}` |
| `/users/refresh` | POST | `{refreshToken}` → Java 轮换刷新；失效时 HTTP 200+`code:401`（Node 语义），小程序会跳登录页 |
| `/users/me` | GET(Bearer) | 401 走 **HTTP 401**（小程序刷新触发器）；成功旧格式 user（含文章/评论数统计字段） |

### 2.2 wechat 扫码域（放 `modules/wechat/api/compat/`）

| 旧路径 | 方法 | 行为要点 |
|---|---|---|
| `/qr-login/session` | POST | `{channel?, env_version?}` → 建会话（**TTL 5 分钟**，Redis 热点态 + DB 审计）+ 生成小程序码（`page=pages/pc-qr-login/index`、`check_path=false`、`width=512`、env_version 覆盖）→ `{sceneId, expiresAt, miniProgramCode(base64 dataURL)}` |
| `/qr-login/session/{sceneId}` | GET | 轮询：pending `{status,expiresAt}`；**confirmed 一次性返回 `{status:'confirmed', token, refreshToken, user}` 并置 completed**（Node 无换票端点，Token 直接随轮询下发——严格复刻）；completed `{status:'completed'}`；过期 200+`code:410` |
| `/qr-login/session/{sceneId}/code.png` | GET | PNG 二进制，`no-store`；支持 `?env_version=` 重新取不同版本码（缓存与版本键关联） |
| `/miniapp/qr-login/entry` | POST | `{sceneId, code}` → jscode2session → 已绑定：置 confirmed+user_id，`{action:'login_ok', client}`；未绑定：存 temp_openid+bindToken(5min)，`{action:'need_register_or_bind', bindToken, client}`。client 为 UA/IP 脱敏描述（复刻 Node describeClient） |
| `/miniapp/qr-login/register-and-confirm` | POST | 复刻 Node（小程序当前 UI 未调用，属预留端点；实现保证语义一致） |
| `/miniapp/qr-login/bind-and-confirm` | POST | 同上（**注意 Node 此端点密码是明文比对**；Java 复刻时仍解 Base64+BCrypt，但按 Node 的字段语义——此端点小程序不调，风险为零） |

### 2.3 横向：X-Request-Time 防重放

小程序每个请求都带 `X-Request-Time`（毫秒），Node 校验偏差 >30s → HTTP 200+`code:400`。Java 兼容层挂同款 Filter（仅兼容路径），偏差容忍取 **5 分钟**（对抗手机时钟不准，比 Node 的 30s 宽松、只松不严，不破坏小程序）。

### 2.4 严格复刻的两个"旧版怪癖"（决策）

1. **未绑定用户扫码需要扫两次**：entry→提示注册/绑定→小程序走 `/users/register|login` 带 openid（openid 绑上，但会话仍 pending）→ 用户再扫一次码 → entry → login_ok → PC 拿到 Token。线上现状即如此。Java 第一版**严格复刻**（配置 `wzblog.wechat.compat.auto-confirm-on-bind` 预留，默认 false——开启则登录/注册带 openid 成功时自动确认其 pending 会话，体验更顺，但默认不引入新行为）。
2. **register 的 openid 绑定**：Node 忽略该字段；Java 善意绑定（修复后小程序注册流程真正闭环，且不改任何协议字段）。

## 4. 实现结构（与现有架构对齐）

```
modules/identity/
  app/WechatIdentityService        （新增：openid 登录/创建/绑定，M8 设计文档 §7 规则）
  app/AuthAppService#issueTokens    （抽取公开方法）
  api/compat/LegacyAuthController   （/users/captcha|register|login|refresh|me、/wechat/*）
  infra/redis/ArithmeticCaptchaStore（算术验证码 MD5 变体）
modules/wechat/                     （全新模块）
  app/QrSessionService              （状态机：Redis 热点 + wechat_qr_sessions 审计）
  app/WechatLoginService            （code 登录编排）
  infra/wechat/WeChatApiClient      （接口）+ Mock / Real 双实现（同 M6 模式）
  infra/wechat/AccessTokenManager   （Redis 缓存 + 单飞刷新）
  api/QrLoginController             （新契约 9 条，按 M8 设计文档）
  api/compat/LegacyQrController     （旧契约 8 条）
common/web/LegacyResponse           （旧壳工具：数字 code、token 顶层、snake_case user）
common/web/LegacyTimestampFilter    （X-Request-Time 校验，仅兼容路径）
ErrorCode + WECHAT_* 14 个码（M8 文档 §13 规格）
```

- 兼容 Controller 全部挂 `@InfrastructureRoute`（免 `/api/v1` 前缀，与媒体路由同机制）。
- SecurityConfig 放开上述旧路径（PUBLIC；`/users/me` 由 Java 过滤器按 Bearer 鉴权出 HTTP 401）。
- 环境变量：`WX_MINIAPP_APPID/SECRET`（用户 .env 现名）为准，`WECHAT_APP_ID/SECRET` 别名双认；缺省→Mock 上游+模块自动关闭（503 `WECHAT_NOT_ENABLED`，密码登录不受影响）。
