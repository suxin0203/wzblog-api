## 1. 部署拓扑
单机 Compose，全部服务在同一自定义桥接网络 `wzblog-net`；只有 `app` 与 MinIO API 绑定全部网卡，其余端口仅绑定回环地址。

```
            Windows 宿主机 (Docker Desktop)
+-----------------------------------------------------------+
| localhost:8080     localhost:9000        localhost:3000   |
|      |                  |                     |           |
|  [ app:8080 ]      [ minio:9000/9001 ]   [ grafana:3000 ] |
|      |                  |                     |           |
|      +------------- wzblog-net ---------------+           |
|      |                  |                     |           |
|  [ mysql:3306 ]    [ redis:6379 ]     [ prom:9090 ]       |
|  volume:mysql-data  volume:redis-data   volume:prom-data  |
+-----------------------------------------------------------+
```

- `app` 通过容器名访问 `mysql:3306`、`redis:6379`、`minio:9000`，不使用 `localhost`。
- 浏览器直传 MinIO 使用 `MINIO_PUBLIC_ENDPOINT`（默认 `http://localhost:9000`）；签名必须针对该地址生成，否则预签名 URL 的 Host 与实际访问不一致会 403。
- Prometheus 只抓取容器网络内的 `app:8080`，不发布端口；Grafana 仅本机访问。

### 1.1 端口
| 服务 | 容器端口 | 宿主机绑定 | 用途 | 是否公网 |
|---|---|---|---|---|
| app | 8080 | `0.0.0.0:8080` | API / Swagger / 健康检查 | 开发机内网；上线经反代 |
| mysql | 3306 | `127.0.0.1:3306` | 本机客户端调试 | 否 |
| redis | 6379 | `127.0.0.1:6379` | 本机 redis-cli 调试 | 否 |
| minio | 9000 | `0.0.0.0:9000` | S3 API、预签名直传 | 仅开发；上线走反代/域名 |
| minio console | 9001 | `127.0.0.1:9001` | 管理控制台 | 否 |
| prometheus | 9090 | `127.0.0.1:9090` | 指标查询 | 否 |
| grafana | 3000 | `127.0.0.1:3000` | 面板（可选） | 否 |
| nginx（可选） | 80/443 | `0.0.0.0:80/443` | HTTPS 与 SSE 反代 | 是（有域名时） |

|---|---|---|---|

## 3. Docker Compose 设计
> 本文只定义结构与关键片段，`docker-compose.yml` 在工程初始化阶段创建。镜像 tag 只写大版本或 `latest`，落地时固定到具体版本或 digest。

### 3.1 服务总表
| 服务 | 镜像（大版本） | 端口 | 卷 | 健康检查 | 启动依赖 |
|---|---|---|---|---|---|
| `app` | 自建 `wzblog-server`（基于 `eclipse-temurin:21-jre`） | 8080 | 无（日志走 stdout） | `GET /actuator/health/readiness` | mysql/redis/minio 均 healthy |
| `mysql` | `mysql:8.0` | 3306→127.0.0.1 | `mysql-data` | `mysqladmin ping` | 无 |
| `redis` | `redis:7` | 6379→127.0.0.1 | `redis-data` | `redis-cli ping` | 无 |
| `minio` | `minio/minio:latest` | 9000/9001 | `minio-data` | `/minio/health/live` | 无 |
| `minio-init` | `minio/mc:latest` | — | — | 一次性任务，退出即完成 | minio healthy |
| `prometheus` | `prom/prometheus:latest` | 9090→127.0.0.1 | `prom-data` | `/-/healthy` | app 启动 |
| `grafana`（可选） | `grafana/grafana:latest` | 3000→127.0.0.1 | `grafana-data` | `/api/health` | prometheus |

### 3.2 关键片段
```yaml
services:
  mysql:
    image: mysql:8.0
    command: ["--character-set-server=utf8mb4", "--collation-server=utf8mb4_0900_ai_ci",
              "--default-time-zone=+00:00"]
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_ROOT_PASSWORD}
      MYSQL_DATABASE: ${DB_NAME}
      MYSQL_USER: ${DB_USERNAME}
      MYSQL_PASSWORD: ${DB_PASSWORD}
      TZ: UTC
    ports: ["127.0.0.1:3306:3306"]
    volumes: ["mysql-data:/var/lib/mysql"]
    healthcheck:
      test: ["CMD-SHELL", "mysqladmin ping -h 127.0.0.1 -uroot -p$$MYSQL_ROOT_PASSWORD --silent"]
      interval: 10s
      timeout: 5s
      retries: 20
      start_period: 60s

  redis:
    image: redis:7
    command: ["redis-server", "--requirepass", "${REDIS_PASSWORD}", "--appendonly", "yes",
              "--maxmemory", "256mb", "--maxmemory-policy", "volatile-lru"]
    healthcheck:
      test: ["CMD-SHELL", "redis-cli -a $$REDIS_PASSWORD ping | grep PONG"]
      interval: 10s
      timeout: 3s
      retries: 10

  app:
    build: { context: ., dockerfile: Dockerfile }
    image: wzblog-server:${APP_VERSION:-local}
    env_file: [.env]
    ports: ["8080:8080"]
    depends_on:
      mysql: { condition: service_healthy }
      redis: { condition: service_healthy }
      minio: { condition: service_healthy }   # 三库全部就绪才启动
    healthcheck:
      test: ["CMD-SHELL", "curl -fsS http://localhost:8080/actuator/health/readiness || exit 1"]
      interval: 15s
      timeout: 5s
      retries: 10
      start_period: 90s
    mem_limit: 1536m
    cpus: 1.5
    logging: { driver: json-file, options: { max-size: "50m", max-file: "3" } }
    restart: unless-stopped
```

- 网络：`networks: { wzblog-net: { driver: bridge } }`，所有服务显式加入；不用 `network_mode: host`（Windows 不支持且破坏隔离）。
- 资源限制用 `mem_limit`/`cpus`（非 Swarm 的 `deploy.resources` 在 `docker compose up` 下不生效）；建议 mysql 1 CPU/1G、redis 0.5/256M、minio 1/512M、prometheus 0.5/512M、grafana 0.5/256M。
- `minio-init` 一次性容器：`mc alias set` + `mc mb -p` 建两个桶 + `mc anonymous set-json` 设公开读策略，退出码 0 即完成；`depends_on: minio: service_healthy`。
- MinIO 镜像内的探测工具以实际镜像为准：官方示例用 `mc ready local`；若镜像不含 `mc`/`curl`，改用自定义 HTTP 探测容器，落地前实测。
- 所有镜像可用 `image@sha256:...` 固定，避免 `latest` 漂移；升级前 `docker compose pull` 并在测试环境验证。
- `app` 镜像需自带 `curl`（健康检查用），在 Dockerfile 中安装并清理 apt 缓存。

## 4. 应用配置
### 4.1 三份配置的职责
| 文件 | 提交仓库 | 内容 | 典型差异 |
|---|---|---|---|
| `application.yml` | 是 | 公共默认：`wzblog.*`、Jackson、MyBatis-Plus、Flyway、Actuator 白名单、日志格式 | 不含任何密码；敏感项写 `${ENV}` |
| `application-local.yml` | 是 | 本地开发：SQL 日志、Swagger 全开、种子数据 | `logging.level.com.wzblog=DEBUG`，连接本机 Compose |
| `application-prod.yml` | 是 | 发布：关闭 Swagger UI 与 SQL 日志、`health.show-details=never`、连接池与超时收紧 | `springdoc.api-docs.enabled=false`，仅内网抓指标 |

`application-local.yml` **不**存放真实密钥，只负责差异项，因此可安全提交。个人机器额外覆盖用 `application-local-private.yml` 并加入 `.gitignore`。

### 4.2 配置绑定
统一前缀 `wzblog.*`，用 `@ConfigurationProperties` + `@Validated` 集中绑定，禁止散落 `@Value`：

| 前缀 | 内容 | 示例键 |
|---|---|---|
| `wzblog.auth` | Token 时效、issuer/audience、登录锁定 | `access-token-ttl`、`refresh-token-ttl`、`issuer` |
| `wzblog.security` | CORS 来源、限流开关 | `cors.allowed-origins`、`rate-limit.enabled` |
| `wzblog.storage` | MinIO 端点、桶、预签名时效、图片上限 | `endpoint`、`public-endpoint`、`presign-ttl` |
| `wzblog.ai` | 端点、模型、超时、配额、工具轮次 | `base-url`、`model`、`timeout-ms` |
| `wzblog.points` | 积分规则与日上限 | `daily-login`、`publish-daily-cap` |
| `wzblog.wechat` | AppID、扫码页路径、会话 TTL | `app-id`、`qr-page` |
| `wzblog.obs` | 慢 SQL 阈值、trace 采样 | `slow-sql-ms`、`trace-header` |
| `wzblog.bootstrap` | 管理员种子开关 | `admin.enabled`、`admin.username` |

```yaml
wzblog:
  auth:
    jwt-secret: ${JWT_SECRET}
    access-token-ttl: 15m
  storage:
    endpoint: ${MINIO_ENDPOINT}
    public-endpoint: ${MINIO_PUBLIC_ENDPOINT}
    access-key: ${MINIO_ACCESS_KEY}
    secret-key: ${MINIO_SECRET_KEY}
  ai:
    base-url: ${AI_BASE_URL:}
    api-key: ${AI_API_KEY:}
    model: ${AI_MODEL:}
    timeout-ms: ${AI_TIMEOUT_MS:60000}
```

### 4.3 启动期校验
`JwtProperties` 上 `@Validated` + `@Size(min = 32)`（以**解码后字节数**为准），并在 `@PostConstruct` 中显式解码校验；不足直接抛异常终止启动，日志只打印「长度不足」不打印密钥。同理校验：`MINIO_PUBLIC_ENDPOINT` 必须是绝对 URL；`CORS_ALLOWED_ORIGINS` 不得含 `*`；`AI_BASE_URL` 非空时 `AI_API_KEY` 必填。启动失败要给出明确原因，而不是空指针。

## 5. 数据库与迁移
### 5.1 启动迁移 vs 独立迁移任务
| 方式 | 适用 | 说明 |
|---|---|---|
| 应用启动时 Flyway（默认） | 本地、演示、单实例 | `spring.flyway.enabled=true`，`clean-disabled=true` |
| 独立迁移步骤（发布用） | 多实例或「先迁移后切流量」 | 流水线先 `flyway migrate`，再滚动 `app`；`app` 设 `spring.flyway.enabled=false` |

```bash
docker run --rm --network wzblog-net \
  -v "$PWD/db/migration:/flyway/sql:ro" \
  -e FLYWAY_URL="jdbc:mysql://mysql:3306/wzblog" -e FLYWAY_USER="$DB_USERNAME" \
  -e FLYWAY_PASSWORD="$DB_PASSWORD" \
  flyway/flyway:latest -locations=filesystem:/flyway/sql migrate
```

多实例风险：Flyway 自带锁表，通常可串行化并发迁移，但 DDL 的元数据锁会阻塞业务查询，失败后可能留下半成品状态；**约定同一时刻只有一个迁移者**。本项目单实例，默认启动迁移即可；扩容时切到独立任务。脚本单一来源为仓库 `db/migration/`，构建时打入 classpath。

### 5.2 备份与恢复
```bash
docker compose exec -T mysql mysqldump -uroot -p"$DB_ROOT_PASSWORD" \
  --single-transaction --quick --routines --triggers --events \
  --set-gtid-purged=OFF --default-character-set=utf8mb4 wzblog \
  | gzip > backup/wzblog_$(date +%Y%m%d_%H%M).sql.gz

docker compose stop app
gunzip -c backup/wzblog_20261024_0200.sql.gz \
  | docker compose exec -T mysql mysql -uroot -p"$DB_ROOT_PASSWORD" wzblog
docker compose start app
```

第一条为备份（Git Bash；先 `set -a; source .env; set +a` 载入变量；PowerShell 用对应语法），后三条为恢复：先停 `app` 避免写入，导入后重启。备份产物落在 `./backup` bind 目录，权限仅当前用户可读。

### 5.3 迁移失败与回滚
- **原则：前滚修复，不修改已执行脚本**。`success=1` 的脚本一旦改动，checksum 校验会在下次启动失败。
- 迁移失败（`success=0`）：先修根因，再写 `V{n+1}__fix_*.sql` 前滚；MySQL DDL 不支持事务回滚，不要假设「失败即无痕迹」。
- 校验和不一致：先确认是否仅换行/编码差异（`.gitattributes` 统一 `*.sql text eol=lf`）。语义未变可用 `flyway repair` 仅重写历史表校验和；语义已变**不用 repair 掩盖**，改为新增迁移并在发布说明记录。
- 发布回滚不还原数据库：采用 expand-contract（先加列/加表、后删旧列），保证上一版本镜像仍能读写新结构。

## 6. MinIO
### 6.1 桶规划
| 桶 | 访问 | 内容 | key 前缀 |
|---|---|---|---|
| `wzblog-public` | 匿名只读（GetObject） | 文章封面、正文图、头像、轮播、商品图 | `articles/{yyyy}/{MM}/`、`avatars/{yyyy}/{MM}/`、`banners/{yyyy}/{MM}/`、`goods/{yyyy}/{MM}/` |
| `wzblog-private` | 私有，仅预签名 | **预留，当前未使用**（无 bizType 落此桶） | `temp/`、`exports/`（预留） |

公开桶只授予 `s3:GetObject`，**不授予 ListBucket**，避免被枚举：

```json
{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"AWS":["*"]},
 "Action":["s3:GetObject"],"Resource":["arn:aws:s3:::wzblog-public/*"]}]}
```

应用使用专用服务账号（非 root），策略限定两个桶的 `GetObject/PutObject/DeleteObject` 与 `temp/` 的 `ListBucket`；root 账号只用于初始化与运维。

### 6.2 直传、签名与生命周期
- 预签名：服务端生成 object key，规则统一为 `{biz}/{yyyy}/{MM}/{uuid}.{ext}`（例如 `articles/2026/10/{uuid}.webp`，`{biz}` ∈ `articles|avatars|banners|goods`，`yyyy/MM` 取 UTC，`uuid` 为 32 位小写 hex）；签名绑定 key + `PUT` + 有效期 5 分钟 + 大小范围；客户端不能指定任意 key。
- 缩略图：同一规则生成 `{biz}/{yyyy}/{MM}/{uuid}_thumb.jpg`，key 写入 `files.thumb_key`，不单独建行、不单独计数。
- 直传后必须 `POST /files/{id}/confirm`；未确认的 `TEMP` 记录 24 小时后清理。
- 生命周期：`temp/` 前缀 1 天过期；中止未完成的分片上传（1 天）；公开桶不设自动过期（内容资产）。
- 孤儿治理在应用层：`ref_count=0` 且 7 天未引用 → **先在 DB 置 `DELETED`（记录删除意图并提交）→ 再删 MinIO 对象 → 失败按退避策略重试并纳入清理任务补偿**；不以对象删除成功作为状态变更前提。MinIO 生命周期只做兜底，不能替代引用计数。
- CORS（浏览器直传必需）：允许来源 `http://localhost:5173`（上线换正式域名），方法 `PUT/GET/HEAD`，允许头 `*`，暴露 `ETag`，`MaxAgeSeconds` 3000。未配置 CORS 时浏览器报跨域而非 403，注意区分。

## 7. 可观测
### 7.1 Actuator
| 端点 | 暴露 | 说明 |
|---|---|---|
| `/actuator/health` | PUBLIC | 仅 `status`，`show-details=never`（prod） |
| `/actuator/health/liveness` | 内部 | 进程存活，供容器重启判断 |
| `/actuator/health/readiness` | 内部 | DB/Redis/MinIO 就绪，供流量接入判断 |
| `/actuator/info` | PUBLIC | 版本、git sha |
| `/actuator/prometheus` | 仅容器网络 | 不发布端口；如需外部抓取，加 IP 白名单或 ADMIN |

`management.endpoints.web.exposure.include=health,info,prometheus`，其余不暴露；`management.endpoint.health.probes.enabled=true`。

### 7.3 Grafana 四类面板
| 面板 | 关键 PromQL | 关注点 |
|---|---|---|
| 流量与错误 | `sum(rate(http_server_requests_seconds_count[5m])) by (uri)`；5xx 占比 `sum(rate(...{status=~"5.."}[5m])) / sum(rate(...[5m]))` | 突增、错误率 >1% 告警 |
| 接口 P95 | `histogram_quantile(0.95, sum by (le,uri) (rate(http_server_requests_seconds_bucket[5m])))` | 对照 8.1 目标值 |
| JVM / 连接池 | `jvm_memory_used_bytes`、`jvm_gc_pause_seconds_sum`、`hikaricp_connections_active`、`hikaricp_connections_pending` | pending 持续 >0 说明池不足或慢 SQL |
| 业务计数 | `rate(order_created_total[5m])`、`rate(ai_tokens_total[5m])`、`rate(points_granted_total[5m])`、限流拒绝数 | 与日志对账 |

### 7.4 日志与追踪
- 输出到 stdout，JSON 单行；字段固定 `ts, level, traceId, userId, module, action, costMs, msg`。
- 入口过滤器生成/透传 `X-Trace-Id` 写入 MDC 与响应头，异步与 SSE 线程手动传递；日志禁止出现密码、token、openid、完整手机号。
- Docker 日志轮转：`max-size=50m`、`max-file=3`；应用不写文件日志（避免卷膨胀）。
- 慢 SQL：MyBatis 拦截器记录 >200ms 的语句（参数脱敏）并带 traceId；生产不引入 p6spy。

### 8.1 镜像构建（多阶段）
```dockerfile

```

镜像非 root 运行；构建阶段可加 `-DskipTests`，测试由 CI 的 `mvn verify` 负责；基础镜像若为 UBI/Alpine，改用对应包管理器安装 `curl`。

### 8.2 版本与发布步骤
- 版本：`MAJOR.MINOR.PATCH`（语义化）+ git 短 sha；镜像 `wzblog-server:0.4.0-a1b2c3d`，另打 `latest` 仅作本地便利，**发布不使用 latest**。
- 步骤：CI 绿并打 tag → `docker compose build app` 并记录镜像 tag → 备份数据库并确认文件非 0 字节 → 执行迁移 → `docker compose up -d app` → 等 `healthy`（`docker inspect --format '{{.State.Health.Status}}' <container>`）→ 冒烟（`/actuator/health` 为 `UP`、登录、文章详情、AI 首字节）→ 观察 10 分钟错误率与 P95 后宣告完成。

### 8.3 回滚
1. 将 `APP_VERSION` 改回上一 tag，`docker compose up -d app`；
2. 数据库**不降级**：上一版本必须能读新结构（expand-contract 保证）；
3. 若新版本已写入旧版本无法解析的数据，前滚修复而不是回滚镜像；
4. 回滚后重跑冒烟，并在发布记录写明原因与后续修复版本。

- [ ] CI 全绿，依赖扫描无高危
- [ ] `.env` 无新增未登记变量，密钥非默认值
- [ ] 数据库备份完成且可解压
- [ ] 迁移脚本只新增、未改动历史文件
- [ ] 镜像 tag 与 git sha 对应

## 10. 安全加固
| 项 | 要求 |
|---|---|
| 端口 | MySQL/Redis/MinIO 控制台/Prometheus/Grafana 一律 `127.0.0.1` 绑定；公网只开 80/443（或 8080 临时演示后立即关闭） |
| MySQL | 应用专用账号，仅授权 `wzblog.*` 的 DML + 必要 DDL；禁用 `FILE`、`SUPER`；root 仅备份使用 |
| Redis | 必须 `requirepass`；`protected-mode yes`；`rename-command` 禁用 `FLUSHALL/CONFIG` 等高危命令；所有 key 带 TTL |
| MinIO | root 仅初始化；应用用服务账号最小权限；公开桶只读不列举；控制台不对外 |
| Actuator | 只暴露 health/info；prometheus 仅内网；`show-details=never`；不暴露 env/heapdump/threaddump |
| CORS | 白名单来源，禁止 `*` 与 `allowCredentials=true` 组合；预检缓存 30 分钟 |
| HTTPS | 有域名时 Nginx/Caddy 终止 TLS；容器内仍用 HTTP；HSTS 按域名启用 |
| 依赖 | CI 跑 `mvn dependency-check`（或 OWASP 插件）与镜像 `trivy image` 扫描；高危阻断合并 |
| 密钥 | 只从环境变量注入；不写入镜像层、不打印、不提交；泄露即轮换并吊销会话 |
| 上传 | 魔数 + 解码 + 像素/体积限制；SVG 拒绝；对象 key 服务端生成 |

Nginx 反代 SSE 的关键配置（否则「看起来不流式」）：`proxy_http_version 1.1`、`proxy_buffering off`、`proxy_cache off`、对 `text/event-stream` 关闭 `gzip`、`proxy_read_timeout 300s`、透传 `Connection: ''`；应用侧同时返回 `X-Accel-Buffering: no` 并每 15 秒心跳。

## 11. 排障手册
| 现象 | 常见原因 | 排查 / 处置 |
|---|---|---|
| `app` 反复重启 | 环境变量缺失、JWT_SECRET 过短、DB 未就绪 | `docker compose logs --tail=200 app`；核对 `SPRING_PROFILES_ACTIVE` 与 `.env` 键名；等 mysql healthy |
| MySQL `Connection refused` | 容器未起、写成 localhost、账号无权限 | `docker compose ps`；容器内必须用 `mysql:3306`；`docker compose exec mysql mysql -u$DB_USERNAME -p` 验证 |
| 时间差 8 小时 | JVM 或 MySQL 时区不是 UTC | 容器 `TZ=UTC`、JVM `-Duser.timezone=UTC`、MySQL `--default-time-zone=+00:00`、JDBC `connectionTimeZone=UTC`；接口只返回带 `Z` 的时间 |
| Flyway checksum mismatch | 改过已执行脚本、换行符变化 | 比对 git 历史；仅格式差异可 `flyway repair`；语义变更写新版本迁移 |
| Redis OOM / 写入失败 | `maxmemory` 过小、大 key、无 TTL | `redis-cli -a ... info memory`、`--bigkeys`；确认 `volatile-lru` 且 key 都有 TTL；扩容而非随手 `FLUSHDB` |
| MinIO 403（服务端调用） | 密钥错、region 不匹配、时钟偏差、桶策略缺失 | 核对 `MINIO_REGION` 与账号；用 `minio/mc` 镜像执行 `mc admin info`、`mc ls` 核对账号与桶策略；校准宿主机时间 |
| 预签名 URL 403 | 过期、方法不符、Host 不一致、签名头被改 | 确认 `MINIO_PUBLIC_ENDPOINT` 与浏览器访问地址完全一致；PUT 时不要额外改 `Content-Type`；5 分钟内使用 |
| AI 请求超时 | 上游不可达、Key 无效、总超时过短 | 先 `curl` 上游端点；看日志中 AI 错误码；确认代理与 DNS；超时后由前端重试，服务端不重试计费请求 |
| SSE 不流式（一次性返回） | Nginx 缓冲、压缩、HTTP/1.0、中间层缓存 | 按第 10 节配置；`curl -N` 直连 8080 对比，定位是应用还是代理 |
| 端口被占用 | 本机已有 MySQL/Redis 或上次容器未退 | `netstat -ano` 找到 PID，再 `tasklist /FI "PID eq <pid>"`；改宿主端口或停旧进程 |
| Docker 磁盘满 | 镜像层、日志、卷膨胀 | `docker system df`；`docker image prune`、`docker builder prune`；日志轮转；`docker system prune -a --volumes` 会删数据，执行前确认卷 |
| 中文乱码 | 连接未指定 utf8mb4 | JDBC 加 `characterEncoding=utf8`，库/表 `utf8mb4_0900_ai_ci`；导入 dump 加 `--default-character-set=utf8mb4` |

## 13. 资源建议
以下为**经验值**，用于本机规划，不是购买建议：

| 资源 | 最低 | 推荐 | 说明 |
|---|---|---|---|
| 内存 | 8 GB | 16 GB | Compose 全家桶约 4~5 GB；IDE + 浏览器 + Maven 另需 4 GB 以上 |
| 磁盘 | 20 GB 空闲 | 50 GB SSD | 镜像约 3~5 GB，MySQL 与 MinIO 随数据增长，备份另计 |
| CPU | 4 核 | 6~8 核 | 压测（k6）时 app 与 MySQL 争用明显 |
| Docker | Docker Desktop（WSL2 后端） | 同上 + 分配 6 GB 内存 | 内存分配过小会导致 MySQL 启动超时 |

零现金成本说明：MySQL、Redis、MinIO、Prometheus、Grafana、Nginx 均为开源软件，本地运行不产生费用；镜像从公共仓库拉取。AI 与微信能力依赖外部账号，其额度、计费与开通条件以官方文档为准，本项目不承诺免费额度；未配置时对应功能关闭，不影响其余演示。
