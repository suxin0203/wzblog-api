## 1. 地址与调试工具

| 环境 | 地址 | 说明 |
|---|---|---|
| 本地后端 | `http://localhost:8021` | `scripts/run.sh` 启动（profile=local） |
| 接口总表（机读） | `http://localhost:8021/v3/api-docs` | OpenAPI 3 JSON，共 155 个 operation |
| Swagger UI | `http://localhost:8021/swagger-ui.html` | 浏览器直接调试 |
| 计划生产 | `https://wzblog-api.suxin23.cn` | 反代到 8021，路径不变 |

- 所有业务接口挂在 **`/api/v1`** 前缀下；例外两类不带前缀：13 条小程序旧协议兼容路由（`/users/*`、`/qr-login/*`、`/miniapp/*`、`/wechat/*`）和 2 条媒体基础设施路由（`/media/{objectKey}`、`/media-upload/{token}`）。
- CORS：开发期全放开（任意 Origin，凭据模式关闭，token 一律走 `Authorization` 头，不用 Cookie）。
- 响应头带 `X-Trace-Id`；限流响应带 `Retry-After`（秒）。

## 2. 全局约定（30 秒版）

- **响应信封**：`{ "code": "OK", "message": "success", "data": {}, "traceId": "…" }`。`code` 是字符串，成功固定 `"OK"`；失败时 HTTP 状态码表达语义（200 不包失败），`data=null`；参数校验失败 `data={"errors":{字段:原因}}`。
- **ID 一律字符串**：JSON 里 BIGINT 输出为 `"1024"`；查询参数按字符串传。
- **时间**：出参 ISO-8601 UTC（`2026-10-24T04:00:00.000Z`）；入参必须带时区（推荐 `Z`）。积分日上限/统计的业务日按 `Asia/Shanghai` 切。
- **列表永不为 null**（空返回 `[]`）；金额/积分/计数一律整数。
- **创建成功返回 201**（注册、发文、发评论、下单、创建分类/标签等）；其余成功 200。
- **分页**：普通分页 `page/pageSize`（默认 20，最大 100；参数名是 `pageSize` 不是 `size`，`PageResult` 回显同名字段）；游标分页 `cursor/size`（默认 20，最大 50），响应 `{ list, nextCursor, hasNext }`。

**错误码必须认识的几个**（全量见 docs/04 §7，108 条）：

| 场景 | HTTP | code | 前端动作 |
|---|---|---|---|
| 未登录 / token 缺失无效 | 401 | `AUTH_UNAUTHORIZED` / `AUTH_TOKEN_INVALID` | 引导登录 |
| access token 过期 | 401 | `AUTH_TOKEN_EXPIRED` | 用 refresh 静默续期后**重放原请求**（见 §3） |
| 越权 / 账号停用 | 403 | `AUTH_FORBIDDEN` / `AUTH_ACCOUNT_DISABLED` | 提示无权限，不要重试 |
| 资源不存在或不可见 | 404 | `*_NOT_FOUND` | 隐藏资源统一 404（含他人草稿/私密文章），**404 ≠ 接口错** |
| 并发修改冲突 | 409 | `ARTICLE_VERSION_CONFLICT` 等 | 提示刷新后重试（乐观锁，请求需带 `version`） |
| 限流 | 429 | `COMMON_RATE_LIMITED` / `AI_QUOTA_EXCEEDED` | 按 `Retry-After` 倒计时；连续 5 次密码错会 `AUTH_ACCOUNT_LOCKED` 锁 15 分钟 |

## 3. 鉴权：双 Token

| Token | 有效期 | 传递方式 | 说明 |
|---|---|---|---|
| access token | 15 分钟 | `Authorization: Bearer <accessToken>` | JWT；过期返回 401 `AUTH_TOKEN_EXPIRED` |
| refresh token | 14 天 | 只在刷新接口提交 | **轮换制**：每次刷新返回新 token 对，旧 refresh 作废；重放已作废的 refresh（401 `AUTH_REFRESH_REUSED`）会触发全家簇吊销，需重新登录 |

**端点**（`/api/v1/auth/*`，见 docs/04 R001~R021 区段）：

1. `GET /auth/captcha` → 注册/登录拿图形验证码（`captchaId` + base64 图）。
2. `POST /auth/register`（201）→ **只返回用户信息，不自动登录、不发 token**；前端注册成功后引导去登录页（回填用户名）。
3. `POST /auth/login` → 返回 token 对（`accessToken`/`expiresIn`/`refreshToken`/`refreshExpiresIn`，**不含用户对象**）；用户资料另调 `GET /users/me`。
4. `POST /auth/refresh` → `{ refreshToken }` 换新 token 对。**失败（401 `AUTH_REFRESH_INVALID`）→ 清本地凭据，跳登录页。**
5. `POST /auth/logout` / `POST /auth/logout-all`（踢掉所有设备）。
6. 找回密码三步：`POST /auth/password/forgot/request` → `verify` → `reset`。

**前端拦截器建议**：401 且 code=`AUTH_TOKEN_EXPIRED` 时，用 refresh 换新 token 并重放原请求；并发请求只允许一个 refresh 在途（其余挂起等待）。

**角色**：`USER`（注册即得）< `EDITOR`（受邀作者，ADMIN 授予）< `ADMIN`（站主）。A 方案（契约 v1.6）的内容主权规则，前端务必按此处理 403/404：

| 动作 | 谁可以 | 其他人收到 |
|---|---|---|
| 改/发/下架/软删/回滚**自己的**文章 | 作者本人 | — |
| 改**他人**文章内容 | 无人能直接改；ADMIN 走接管 `POST /admin/articles/{id}/takeover` 后才可改 | 公开文章 → 403；草稿/私密/已删 → 404 |
| 恢复 / 彻底删除（purge）/ 置顶 / 后台文章列表 | 仅 ADMIN | EDITOR 一律 403 |
| 审核**自己文章下他人**的评论 | 文章作者（不能审自己的评论） | 其他 EDITOR 403 |
| 全站评论 / 留言板审核 | 仅 ADMIN | — |
| AI 摘要/标签 | 仅文章作者本人 | 他人 403 |

## 4. 分域对接清单

> 只列入口和顺序，字段细节查 docs/04 对应 R 号行。

**公开阅读（游客可用）**：文章列表 `GET /articles`（游标）、详情 `GET /articles/{slug}`、置顶 `GET /articles/pinned`、热门 `GET /articles/top`、搜索 `GET /articles/search`、归档 `GET /articles/archive`；分类 `GET /categories`、标签 `GET /tags`、轮播 `GET /banners`、友链 `GET /friend-links`、公开配置 `GET /public/configs`。阅读上报 `POST /articles/{id}/view`（同一用户/游客每日去重）。

**账号资料**：`GET /users/{id}/profile` 公开主页；登录用户 `GET/PUT /users/me`、改密 `PUT /users/me/password`、会话管理 `GET /users/me/sessions`（可吊销单条）。点赞/收藏记录 `GET /me/likes`、`GET /me/favorites`；我的文章 `GET /me/articles`（作者工作台列表）。

**作者工作台**：
1. 传图：`POST /files/presign` → 直传 `PUT /media-upload/{token}`（裸字节，不套响应壳）或 `POST /files/upload`（multipart，单文件 ≤5MB）→ `POST /files/{id}/confirm` → 引用时 `GET /files/{id}/url` 换签名 URL。
2. 写文：`POST /articles`（201）。正文 Markdown；正文图/封面 key 必须是**当前登录人或（ADMIN 代改时）资源所有者**上传的，保存时后端自动 claim 引用。
3. 编辑体 `GET /articles/{id}/edit`、保存 `PUT /articles/{id}`（**必须回传 `version`**，冲突 409）；发布 `POST /articles/{id}/publish`、下架 `…/unpublish`、软删 `DELETE /articles/{id}`（进回收站，可逆）。
4. 修订：`GET /articles/{id}/revisions`、回滚 `POST /articles/{id}/revisions/{revisionNo}/restore`。
5. AI 辅助：`POST /articles/{id}/ai/summary`、`/ai/tags`（仅作者；结果只展示，不自动写入）。
6. slug：**PUBLISHED 后不可改**（409 `ARTICLE_SLUG_IMMUTABLE`）；下架（ARCHIVED）后可改。

**互动**：评论树 `GET /articles/{articleId}/comments`（根游标 + `rootId` 拉子评论）；发评论 `POST /articles/{articleId}/comments`（游客受 `comment.guest_enabled` 开关）；删自己评论 `DELETE /comments/{id}`；点赞 `POST/DELETE /comments/{id}/like`；文章点赞/收藏 `PUT/DELETE /articles/{id}/reactions/{type}`（`type=LIKE|FAVORITE`，幂等，状态查 `GET /articles/{id}/reactions/me`）。审核接口在 `/admin/comments`（作者限自己文章，ADMIN 全站）；留言板 `/guestbook` 公开读、`/admin/guestbook` ADMIN 管。

**积分商城**：账户 `GET /points/account`（余额/流水/称号）、流水 `GET /points/ledger`；商品 `GET /points/goods`；下单 `POST /points/orders`（**带 `idempotencyKey`**，重复提交同 key 返回原订单）；取消 `POST /points/orders/{orderNo}/cancel`；订单查询 `GET /points/orders`、`GET /points/orders/{orderNo}`。

**通知**：未读数 `GET /notifications/unread-count`；列表 `GET /notifications`；已读 `POST /notifications/read`、全部已读 `POST /notifications/read-all`；实时推送 `GET /notifications/stream`（SSE，登录态）。SSE 事件名/字段见 docs/04 §5；断线用 `Last-Event-ID` 续传，服务端按事件 ID 去重不重推。连接上限每用户 3 条，超限 429。

**AI 问答**：`POST /ai/chat/stream`（SSE 流式）；游客续会话带 `X-AI-Session-Token`；配额 `GET /ai/quota`；会话历史 `GET /ai/sessions/{sessionId}/messages`；反馈 `POST /ai/messages/{messageId}/feedback`。超配额 429 `AI_QUOTA_EXCEEDED`（带 `Retry-After`）。

**管理后台（ADMIN）**：`/admin/*` 全域 —— 文章管理+接管/恢复/purge、评论/留言审核、分类/标签/轮播/友链/配置、用户管理、积分调整 `POST /admin/users/{userId}/points`、商品/称号/订单履约 `POST /admin/points/orders/{orderNo}/transition`、看板 6 接口、审计日志、AI 会话管理、文件清理。所有治理动作后端写审计并通知作者，前端无需额外调用。

## 5. 本地联调步骤

1. 起依赖（Docker）：本地 MySQL 8（`local-mysql8`，库 `wzblog`）+ Redis（`local-redis`，DB 1）——日常开发容器，常驻即可。
2. 建表：Flyway 启动时自动跑 `db/migration/V1__*.sql` + `V2__*.sql`（32 表 + 种子分类）。
3. （可选，推荐联调）灌调试数据：`db/debug-data.sql` 一次性填满 32 张表（非幂等，只能执行一次）。
4. 启动：`./scripts/run.sh`（等价 `mvn spring-boot:run -Dspring-boot.run.profiles=local`，端口 8021）。联调期可用 `WZBLOG_CAPTCHA_ENABLED=false` 关闭图形验证码方便自动化（默认开启）。
5. 冒烟：`GET /api/v1/ping` → `{"code":"OK"}`。

**调试账号**（密码统一 `Passw0rd1`，来自 `db/debug-data.sql`）：

| 账号 | 角色 | 用途 |
|---|---|---|
| `debug_admin` | ADMIN | 站主/后台全功能 |
| `debug_editor` | EDITOR | 受邀作者（写自己的文章） |
| `debug_reader` / `debug_guest` / `debug_newbie` / `debug_coder` | USER | 读者互动/积分/下单 |
| `debug_disabled` | DISABLED | 验证 403 `AUTH_ACCOUNT_DISABLED` |
| `deleted_1008` | 已注销 | 验证注销后资料展示 |

## 6. 常见踩坑

1. **404 不一定是 bug**：他人草稿/私密/已删文章、隐藏资源统一 404，不泄露存在性。
2. **乐观锁**：所有文章保存必须带最新 `version`；多人同时编辑后保存会 409，前端应提供"刷新合并"路径。
3. **ADMIN 的 403**：ADMIN 打开他人文章的编辑体之前必须先调 takeover；前端管理端应有"接管"按钮（输入可选 reason），接管后 author 变更会通知原作者。
4. **媒体引用**：正文图 key 必须来自本人上传（或恢复历史修订时由后端 recorded 路径处理），引用他人 key 保存会 422/403。
5. **下单幂等**：下单按钮防抖之外必须生成 `idempotencyKey`（UUID，用户/会话维度），网络重试复用同 key。
6. **SSE**：EventSource 不支持自定义 header 时用 token 查询参数方案前先看 docs/04 §5 的约定；重连必须带 `Last-Event-ID`。
7. **限流**：登录/评论/上传/AI 都有限流；收到 429 读 `Retry-After` 做倒计时，不要立即重试（密码连续错误 5 次锁 15 分钟）。
8. **小程序**：已上线小程序走第 9 节旧协议，**不要**混用 `/api/v1`。
9. **置顶文章不进信息流**：`GET /articles` 固定排除 `is_pinned=1` 的文章，置顶内容由 `GET /articles/pinned` 单独拉取（首页应渲染"置顶区 + 信息流"两块）。这是有意设计，不是数据丢了。置顶统一走 `GET /articles/pinned`，`GET /articles` 不接受 `pinned` 参数。

## 7. 旧协议兼容（仅已上线小程序）

小程序现有代码零改动可继续使用以下 13 条旧协议路由（响应壳不同：数字 code、HTTP 恒 200、顶层 `token` 字段、snake_case 字段），协议细节见 [13-微信扫码复原计划](13-微信扫码复原计划.md)：

| 组 | 路由 |
|---|---|
| `/users/*` | `GET captcha`、`POST register`、`POST login`、`POST refresh`、`GET me` |
| `/qr-login/*` | `POST session`（建会话+取小程序码）、`GET session/{sceneId}`（轮询）、`GET session/{sceneId}/code.png` |
| `/miniapp/*` | `POST qr-login/entry`、`POST qr-login/register-and-confirm`、`POST qr-login/bind-and-confirm` |
| `/wechat/*` | `GET openid/{code}`、`GET userinfo/{openid}` |

> M8 新契约扫码登录（`/api/v1/auth/qr/*`、`/auth/wechat/*`，R139~R147）暂未实现；实现后新前端优先用新契约。

## 8. 对接验收清单

- [ ] 登录/刷新/登出闭环，401 静默续期不闪烁
- [ ] 游客浏览、搜索、评论（开关开时）正常
- [ ] 作者：传图→写文→发布→编辑（version 回传）→下架→软删 全流程
- [ ] 403/404 场景提示正确（含 ADMIN 未接管改他人文章）
- [ ] 点赞/收藏幂等，计数与明细一致
- [ ] 下单幂等键生效（双击不重复扣积分）
- [ ] SSE 通知实时到达，断线续传不重复
- [ ] 429 时按 `Retry-After` 倒计时
