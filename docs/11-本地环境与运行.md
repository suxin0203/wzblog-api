## 3. 启动与测试

```bash
# 每个新终端先加载环境（JDK 21 + Maven + .env）
source scripts/env.sh

# 编译
scripts/mvn.sh -q -DskipTests compile

# 全量测试（Testcontainers 会启动临时 MySQL/Redis，用本地镜像）
scripts/mvn.sh test

# 启动应用（8021，连 local-mysql8 的 wzblog / local-redis DB1）
scripts/run.sh

# 冒烟
curl -i http://localhost:8021/api/v1/ping
curl -i http://localhost:8021/api/v1/users/me   # 期望 401 AUTH_UNAUTHORIZED
# Swagger: http://localhost:8021/swagger-ui.html
```

> 本地验证码默认开启；调试时可临时 `WZBLOG_CAPTCHA_ENABLED=false scripts/run.sh`。
> 管理员账号由 `AdminBootstrap` 按 `.env` 创建；密码不打印。

## 5. 与设计文档的已知差异

1. **文件存储**：M5 的 MinIO 改为「本地磁盘默认 + MinIO 可选 adapter」；`files.bucket` 写 `local`，对象 key 规则不变。
2. **MySQL/Redis**：复用现有容器（3306/6379），不使用 3307/6380；库名与 Redis DB 隔离。
3. **邮件**：未接 SMTP；找回密码验证码由 `LoggingVerificationCodeSender` 输出，仅在 `WZBLOG_LOG_VERIFICATION_CODE=true` 时打印验证码（本地默认 true，生产必须 false）。
4. **头像**：M1 只保存 `avatarKey`，M5 实现后补 `claimByKey` 引用计数。
5. **管理审计**：M1 写 `login_audits`；`audit_logs` 的统一写入在 M7 接入。
6. **OpenAPI 注解**：M2 起补 `@Operation`，M1 先由 springdoc 自动扫描路由。
7. **JaCoCo 数据文件**：Windows 下 surefire 经 `cmd.exe` 转发 fork 命令会破坏含中文的绝对路径，故 `jacoco.exec` 写入系统临时目录（`${java.io.tmpdir}/jacoco-wzblog.exec`），报告仍在 `target/site/jacoco/`。
8. **Mapper SQL 风格**：采用 MyBatis 注解 + 文本块（`<script>`），未用 XML；后续复杂聚合 SQL 视规模再迁 XML，契约不变。
9. **M5 预签名语义**：本地模式下 `uploadUrl` 为本服务 `PUT /media-upload/{token}`（HMAC+TTL 自校验），TEMP 短期读用 `/media/{key}?exp&sig`；MinIO 预签名待接入 MinIO adapter 时替换，业务契约不变。
10. **M5 清理互斥**：ShedLock 改为 Redis `SET NX EX` 锁（`wzblog:media:cleanup-lock`，30 分钟 TTL），无新增表与依赖；WebP 不做解码校验（JDK 无原生解码器），仅魔数校验、尺寸留空。
11. **统一前缀豁免**：`@InfrastructureRoute` 标注的 RestController（本地媒体路由）不加 `/api/v1` 前缀。
12. **限流（已升级）**：M3 评论/留言、M6 AI 配额、M5 presign 统一走共享组件 `common/ratelimit/SlidingWindowRateLimiter`（`lua/rate_limit_sliding_window.lua`，ZSET 原子清理-计数-写入，一次 EVALSHA）。短窗按各场景秒数、日窗为 24h 滚动窗口；Retry-After 为窗口内最早记录的实际剩余秒数。
13. **M3 评论游标**：列表采用 Base64URL 偏移量游标（Mapper 为 OFFSET 分页），对外不透明；评论树子回复每根上限 200 条。
14. **M3 SSE**：单实例内存注册表（每用户 3 连接、30 分钟超时、15s 心跳、Last-Event-ID 续传）；多实例 Redis Pub/Sub 为演进项。
15. **M3 对账**：候选集 = 明细聚合 ∪ 计数非零文章（覆盖"漂移但无明细"）；修复仅经 M2 `ArticleCounterService` 按差值收敛。
16. **M4 幂等插入**：流水/通知不用 `INSERT ... ON DUPLICATE KEY UPDATE`（不回填自增主键），改普通 INSERT + 事务内捕获 `DuplicateKeyException`（MySQL 域内安全）；并发重复回读 winner 返回 duplicate 结果。
17. **M4 LIKE 反转**：按正向幂等键精确回查（`like:{articleId}:{actorId}`），不用 biz 汇总（会把其他点赞者一起扣）。
18. **M4 DAILY_LOGIN**：每日 1 次由幂等键保证，不设日上限（调用 grant 的 dailyCap=0）。
19. **M6 上游**：默认 `wzblog.ai.provider=mock`（确定性应答，含工具调用演示）；`openai` 走兼容端点非流式调用 + 服务端分片下发 SSE（协议一致，真流式解析待真实 Key 后启用）。
20. **M6 配额**：滑动窗口（同 12 条共享组件）；并发 SSE 用 Redis 计数 + 90s TTL 兜底（计数器非限流窗口）。
21. **M2 端口出参**：`listTags/listCategories` 改返回 port 层 `TaxonomyBrief`，跨模块不暴露 api VO（ArchUnit 约束）。
22. **M7 配置 JSON 列**：`site_configs.config_value` 为 JSON 类型，写入按 `value_type` 编码（STRING 加引号/布尔裸值/JSON 原样）；读取侧统一去引号。
23. **M7 预聚合**：数据一律经各模块 app 端口（M1 注册数/M2 发布数与日阅读 drain/M3 评论与互动/M4 积分合计/M6 今日消息）；article-rank 复用 M2 公开排行接口。
24. **M7 互斥锁**：日统计任务用 Redis SETNX（30 分钟 TTL），与 M3/M5 对账任务同口径。
25. **M6 对话线程池**：有界队列（4 线程 × 排队 64）+ Abort 拒绝，打满映射 429 `AI_CONCURRENCY_LIMITED`；队列上限可用 `wzblog.ai.max-concurrent` 之外再调（跨实例并发仍由 Redis 计数兜底）。
26. **已知取舍（不修）**：`SecurityConfig.unmappedRequest` 对未命中白名单/业务规则的请求多执行一次 `getHandler()` 路由解析，换取未知路径返回 404 JSON 而非 401（语义正确性优先于单次解析开销）。
28. **M5 去重域**：sha256 去重限定同一上传者（`selectDedupCandidate` 带 `uploader_id`）——跨用户字节相同各自成行不做别名，避免所有权校验把合法上传误判 403；代价是不同用户可存相同字节的对象。
29. **M6 并发名额**：CAS release-once（onTimeout/onError 后 Spring 还会触发 onCompletion，双释放会负漂移）；回调注册前的异常（resolveSession 403/404 等）由外层 catch 立即释放。AI 上下文不重复注入新提问（已落库的最新消息即问题）；收口提示仅在用过工具时追加。
31. **OpenAPI 注解（正式关闭）**：不批量补 `@Operation`——springdoc 自动扫描已完整导出路由/参数/响应类型，Swagger 可用；注解属锦上添花，相关任务标记完成。
32. **EXPLAIN 证据（登记不阻塞）**：索引设计在 V1 DDL（含联合索引与覆盖设计）、行为正确性由 99 个集成测试保障；执行计划文本不阻塞发布，留待压测阶段与 k6 报告一并产出归档。
34. **M8 兼容层**：`@InfrastructureRoute` 免 /api/v1 前缀；`LegacyTimestampFilter` 仅旧路径；refresh 不轮换（小程序沿用旧 refreshToken）；码 PNG/会话态 Redis TTL=会话时长；`WechatIdentityFacade` 纯类型隔离跨模块（ArchUnit 抓过两次泄漏后建立）。
33. **banner 定制**：`banner.txt` + 默认开启（用户个性化定制，2026-10-26 入库）。
30. **multipart 边界**：`spring.servlet.multipart.max-file-size=5MB` 与业务上限对齐（Boot 默认 1MB）；`server.tomcat.max-swallow-size=8MB` 保证拒绝超大请求时仍读完 body 再回 4xx JSON（默认 2MB 直接掐连接）。`MaxUploadSizeExceededException` 统一映射 400 `FILE_SIZE_EXCEEDED`（保持契约 HTTP-code 对应表，不另设 413）。
27. **M2 详情缓存策略**：版本键缓存（`content:article:{id}:v{version}`）而非删除失效——内容/元数据类变更 bump version 即轮换键，旧键自然过期，规避"DEL 与并发回填竞争"问题；可见性判断每次先查库（未发布/已删即时 404）。不变式分两层：**内容/元数据变更必须递增 version**（updateContent/publish/unpublish/pin/unpin/softDelete/restore）；**计数类（view/like/favorite/comment）UPDATE 有意不递增 version**（否则每次浏览轮换键，命中率归零）——缓存体不承载计数，命中后用 detail() 为可见性判断取出的新鲜行覆盖四计数（`withFreshCounters`）。
