## 1. 全局约定
### 1.1 前缀、方法与路由
- 所有业务路由统一前缀 `/api/v1`，由 `WebMvcConfigurer#configurePathMatch` 注入，Controller 不写前缀。
- 字面路径段全小写、以中划线分词（`logout-all`、`friend-links`）；路径参数统一 `{camelCase}`（`{articleId}`、`{orderNo}`、`{sessionId}`）。
- 方法语义：`GET` 读；`POST` 创建或动作；`PUT` 全量更新或幂等设置；`DELETE` 删除或取消。**不使用 PATCH**。
- 路由数量与命名以第 2 节为唯一事实来源；模块文档不得增删、改名、移动，新增必须先改 00 §4。
### 1.2 认证
- 请求头 `Authorization: Bearer <accessToken>`；Access Token 为 JWT HS256，15 分钟。
- 游客 AI 会话额外使用 `X-AI-Session-Token`（仅 `/ai/sessions/*` 与 `/ai/chat/stream` 续用）；登录用户忽略该头。
- 每个受保护请求由 M1 回库校验用户存在且 `status=ACTIVE`；`DISABLED` 返回 403 `AUTH_ACCOUNT_DISABLED`。
- SSE 使用 `fetch` 流式读取并带 `Authorization`，**禁止**原生 `EventSource`，**禁止**把 Token 放 query。
### 1.3 响应体
```json
{ "code": "OK", "message": "success", "data": {}, "traceId": "0199a1b2c3d4e5f6" }
```

- `code` 为字符串；成功固定 `OK`（HTTP 200/201）。失败时 `data=null`；仅参数校验失败时 `data={"errors":{"字段":"原因"}}`。
- 每次请求返回 `traceId` 并写响应头 `X-Trace-Id`；上游错误同样带该头。
- `BIGINT` ID 在 JSON 中一律为**字符串**（`"1024"`）；查询参数以字符串接收再转 `long`。
- 列表永不为 `null`，无数据返回 `[]`；金额、积分、计数一律整数，禁止浮点。
- 出参时间为 ISO-8601 UTC（`2026-10-24T04:00:00.000Z`）；入参时间必须带时区，推荐 `Z`。
- 业务日（积分日上限、阅读去重、统计）按 `Asia/Shanghai` 切分，区间换算为 UTC `[D-1 16:00Z, D 16:00Z)`。
- **创建成功用 201**（注册、创建用户/文章/分类/标签/商品/称号/轮播/友链/评论/留言/反馈/订单/扫码会话）；其余成功 200，幂等重放 200。
### 1.4 二进制接口例外
- `GET /auth/qr/sessions/{sceneId}/code` 成功返回 `Content-Type: image/png` 裸字节，**不套响应壳**，但仍返回 `X-Trace-Id`。
- 该接口失败时仍返回 JSON 错误体（404/409/502），前端按 `Content-Type` 区分；其余接口不另设二进制例外。
### 1.5 HTTP 状态映射
| 场景 | HTTP | 代表 code |
|---|---|---|
| 成功读取/更新/动作 | 200 | `OK` |
| 创建成功 | 201 | `OK` |
| 参数/格式/游标/枚举非法 | 400 | `COMMON_VALIDATION_ERROR`、`AUTH_CAPTCHA_INVALID`、`REACTION_TYPE_INVALID` |
| 未登录、令牌缺失/无效/过期 | 401 | `AUTH_UNAUTHORIZED`、`AUTH_TOKEN_INVALID`、`AUTH_TOKEN_EXPIRED`、`AUTH_REFRESH_INVALID`、`WECHAT_TICKET_INVALID` |
| 无权限、账号停用、访客功能关闭 | 403 | `AUTH_FORBIDDEN`、`AUTH_ACCOUNT_DISABLED`、`COMMENT_GUEST_DISABLED`、`FILE_PRESIGN_FORBIDDEN` |
| 资源不存在或不可见 | 404 | `COMMON_NOT_FOUND`、`ARTICLE_NOT_FOUND`、`FILE_NOT_FOUND` |
| 唯一冲突、状态不允许、幂等冲突 | 409 | `ARTICLE_SLUG_CONFLICT`、`ORDER_STATE_INVALID`、`FILE_IN_USE`、`COMMON_IDEMPOTENCY_CONFLICT` |
| 已过期/已消费的凭证 | 410 | `WECHAT_QR_EXPIRED`、`AUTH_RESET_TOKEN_EXPIRED`、`AI_SESSION_EXPIRED` |
| 业务规则拒绝 | 422 | `POINTS_INSUFFICIENT`、`AUTH_BAD_CREDENTIALS`、`ARTICLE_IMAGE_INVALID` |
| 限流（带 `Retry-After`） | 429 | `COMMON_RATE_LIMITED`、`AI_QUOTA_EXCEEDED` |
| 系统异常 | 500 | `COMMON_INTERNAL_ERROR` |
| 上游返回错误 | 502 | `AI_UPSTREAM_ERROR`、`AI_TOOL_FAILED`、`WECHAT_API_ERROR` |
| 功能关闭/服务不可用 | 503 | `AI_DISABLED`、`WECHAT_NOT_ENABLED`、`NOTIFY_STREAM_UNAVAILABLE` |
| 上游超时 | 504 | `AI_UPSTREAM_TIMEOUT` |

> 同一 code 只绑定一个 HTTP，以第 7 节为准；业务错误不得用 200 包裹失败。

## 3. 权限矩阵
| 标记 | 判定 | 能力边界 |
|---|---|---|
| `PUBLIC` | 不校验身份 | 只读公开资源或公共动作（登录/扫码/换票）；不得返回个人数据 |
| `OPTIONAL` | 有 Token 则解析，无则匿名 | 匿名返回公开字段；登录后追加 `liked`、本人 PENDING、游客会话等个性化字段 |
| `USER` | 任一 `ACTIVE` 用户 | 仅操作本人资源；跨用户 ID 按 404 处理，不泄露存在性 |
| `EDITOR` | `EDITOR` 或 `ADMIN` | 受邀作者：只能编辑自己的文章、发布/下架/删除自己的文章、审自己文章下**他人**的评论、AI 辅助自己的文章、文件预签名；不能管分类标签、置顶、留言板、全站评论、用户、积分、配置 |
| `ADMIN` | 仅 `ADMIN` | 站主：文章治理（软删/恢复/purge/置顶/接管）、分类标签、全站评论/留言板、用户、积分商城、订单、配置、轮播、友链、看板、审计、AI 后台、文件清理；也可作为作者写自己的文章 |
| `OWNER` | 已登录且为资源所有者 | 本人评论/留言/订单/文件/会话；`ADMIN` 可越过；他人资源按 404 |

**EDITOR 与 ADMIN 的差异（v1.6，A 方案）**：EDITOR 只能编辑自己的文章，不能编辑他人文章；可以审自己文章下他人的评论，但不能审自己写的评论；不能管分类标签、置顶、留言板、后台文章列表。ADMIN 拥有站点治理能力，但**改他人正文必须先接管**（`POST /admin/articles/{id}/takeover`），不做静默改稿。ADMIN 对 OWNER 资源的越过只适用于文件删除、会话等资源，不适用于文章正文。

**文章越权语义**：非作者访问已公开文章（`PUBLISHED + PUBLIC`）→ 403 `ARTICLE_FORBIDDEN`；草稿/PRIVATE/UNLISTED/ARCHIVED/已删 → 404 `ARTICLE_NOT_FOUND`，不泄露存在性。ADMIN 不豁免，必须先接管。

**文件引用的归属判定**：请求中新增/更换的图片，`files.uploader_id` 必须是业务资源所有者（如文章作者）或当前操作人，ADMIN 可越过；回滚修订等恢复服务端已存内容时 key 不来自请求，走 `claimRecordedByKey`，不校验上传者。文章软删不释放引用；purge 才释放。

**OWNER 判定规则**：一律用 JWT `sub` 与资源外键比对，**不接受** query/body 传入的 `userId` 作为归属依据；归属失败与不存在返回同一 404，仅“存在但角色不足”返回 403；文章写操作按上面的“文章越权语义”区分 403/404；归属校验在 `app` 层执行（路由注解之外的第二道）；`/users/{id}/profile` 为 PUBLIC 白名单读，不属 OWNER 语义。

## 5. 请求公共规范
### 5.1 分页
| 方式 | 参数 | 默认/上限 | 响应 | 适用 |
|---|---|---|---|---|
| 偏移 | `page`、`pageSize` | `page=1`；`pageSize=20`，最大 100 | `PageResult<T>` | 后台列表、`/me/articles`、通知、订单/流水 |
| 游标 | `cursor`、`size` | `size=20`，最大 50（搜索/后台另限） | `CursorResult<T>` | 信息流、评论、留言、我的点赞/收藏、AI 消息 |

- `page<1`、`pageSize`/`size` 越界 → 400 `COMMON_VALIDATION_ERROR`，不静默纠正。
- 同一接口不得同时接受 offset 与 cursor；前台信息流/搜索禁止 offset 深翻页。
### 5.2 游标编码
- `cursor` 为不透明 Base64URL（无填充），内容 `"{排序键}:{id}"`（如 `"{publishedAtEpochMs}:{id}"`）。
- 客户端原样回传，不得解析或拼装；非法/篡改 → 400 `COMMON_VALIDATION_ERROR`。
- 首页不传；`hasNext=false` 时 `nextCursor=null`；游标只保证同一排序口径下不重不漏。
### 5.3 排序白名单
| 接口 | 允许值 | 默认 |
|---|---|---|
| `/articles` | 固定 `publishedAt DESC, id DESC` | 不接收 `sort` |
| `/articles/top` | `type∈{view,like,favorite,comment}`，`limit≤10` | `view` |
| `/admin/articles` | `sort∈{updatedAt,createdAt,publishedAt}` | `updatedAt` |
| `/admin/dashboard/article-rank` | `metric∈{view,like,favorite}` | `view` |
| `/admin/banners`、`/admin/friend-links`、公开轮播/友链 | 固定 `sortOrder ASC, id ASC` | — |
| 其余列表 | 固定 `createdAt DESC, id DESC`（评论子级为 `ASC`） | — |

- 白名单外排序一律 400；不接受列名、SQL 片段、`orderBy` 透传。
### 5.4 筛选参数命名
- 统一 camelCase：`keyword`、`categoryId`、`tagId`、`authorId`、`status`、`visibility`、`deleted`、`userId`、`type`、`channel`、`bizType`、`metric`、`limit`、`from`、`to`。
- `keyword` ≤50；`year` 2000~2100、`month` 1~12 且必须与 `year` 成对。
- 时间筛选取 ISO-8601（默认左闭右开）；**唯一例外**：6 个看板接口的 `from`/`to` 为 `YYYY-MM-DD`（`Asia/Shanghai` 自然日、闭区间）。
- 枚举筛选传大写字符串，未知值 400；不传表示“全部”，不接受空串。
### 5.5 Idempotency-Key 与并发控制
- 格式 8~64 位可见 ASCII（`0x21~0x7E`），按“用户 + 键”24 小时内唯一。
- **必带**：`POST /points/orders`；缺失/非法 → 400 `COMMON_VALIDATION_ERROR`，不建单、不扣分。
- **可选**：`POST /articles/{articleId}/comments`、`POST /guestbook`；未带由限流兜底。
- 同键同体 → 返回首次结果（订单为 200 + 同一 `orderNo`），不重复扣减或扣库存；同键不同体 → 409 `COMMON_IDEMPOTENCY_CONFLICT`。
- 其余写接口不用幂等键，靠唯一键、条件更新与“状态设置”语义保证幂等。
- **`If-Match`/`ETag` 默认不使用**：仅文章更新用请求体 `version`（int 必填）做乐观锁，冲突 409 `ARTICLE_VERSION_CONFLICT`；其他资源不暴露版本号，不支持 HTTP 条件请求。
- 409 时客户端应重新拉取最新状态再决定是否重试，禁止自动无限重试。
## 6. SSE 协议
### 6.1 通用
- 端点：`POST /api/v1/ai/chat/stream`、`GET /api/v1/notifications/stream`。
- 响应头：`Content-Type: text/event-stream;charset=UTF-8`、`Cache-Control: no-cache`、`Connection: keep-alive`、`X-Accel-Buffering: no`、`X-Trace-Id`；Nginx 侧 `proxy_buffering off`。
- 客户端一律 `fetch` + `ReadableStream`，请求头带 `Authorization`；**不使用 `EventSource`**，Token 不得放 query。
- 帧格式：`event: <name>` + `data: <单行 JSON>` + 空行；JSON 为 UTF-8、不换行、不转义中文。
- 心跳：每 15 秒一行注释帧 `: ping`，不计入消息数、不重置计时。
- 首帧前必须完成鉴权、配额、参数与归属校验；未通过返回普通 JSON 错误与 4xx/5xx。**响应已提交后不得改 HTTP 状态码**。
### 6.2 `/ai/chat/stream` 五事件
| 事件 | data 字段 | 时点 |
|---|---|---|
| `session` | `sessionId`、`sessionToken`（游客有值，登录 null）、`expiresAt`（游客为创建+24h） | 首帧，仅一次 |
| `tool` | `name`、`brief`、`status`（`start`/`end`）、`resultCount`（`start` 为 null） | 每次工具调用两帧 |
| `delta` | `text` | 增量文本，可多帧 |
| `done` | `messageId`、`usage{promptTokens,completionTokens}`、`finishReason`（`stop`/`length`/`tool_limit`/`interrupted`/`error`） | 终帧，之后关闭 |
| `error` | `code`、`message`（中文可读，无堆栈/上游原文） | 失败终帧，之后不再发事件 |

```text
event: session
data: {"sessionId":"01JC8Z3K7Q9V2M4T6B8X0D1F2G","sessionToken":"wzai_7Qb2...","expiresAt":"2026-10-25T04:00:00.000Z"}

event: delta
data: {"text":"Java 21 的虚拟线程适合大量阻塞 IO，"}

event: done
data: {"messageId":"1839028172639400001","usage":{"promptTokens":812,"completionTokens":236},"finishReason":"stop"}
```

- 顺序固定：`session` →（`tool` start → `tool` end）* → `delta`* → `done`；失败以 `error` 收尾，之后不再发任何事件。
- 游客续用会话必须带 `X-AI-Session-Token`：缺失 401 `AI_GUEST_TOKEN_INVALID`，不匹配 403 `AI_SESSION_FORBIDDEN`，超 24 小时 410 `AI_SESSION_EXPIRED`。
- 客户端断开或 Emitter 超时：取消上游、落库 `INTERRUPTED`，不再发 `done`/`error`。
- 终止标记固定 `event: done`（或 `error`），**不使用** `data: [DONE]`。
### 6.3 `/notifications/stream`
- 建连先发 `retry: 3000`，随后 `event: ready`，data 为 `{"unreadCount":n}`。
- 通知事件：`id: {notificationId}` + `event: notification` + `data` 为 `{id,type,title,content,linkType,linkId,createdAt}`。
- `Last-Event-ID` 存在时按 `id > 该值` 补发最多 50 条（升序），再发 `ready`；重复由客户端按 `id` 去重。
- 每 15 秒 `: ping`；Emitter 超时 30 分钟，客户端按 `retry` 重连带 `Last-Event-ID`。
- 连接上限：每用户 3 条、每实例 2000 条；超限 429 `NOTIFY_STREAM_LIMITED`，推送关闭 503 `NOTIFY_STREAM_UNAVAILABLE`。
- 降级：推送失败不影响 DB 落库，前端轮询 `/notifications` 与 `/notifications/unread-count`。

## 8. 错误处理约定
- **校验错误**：统一 400，`data={"errors":{"字段":"原因"}}`；多字段全返回，字段名为 DTO 属性名；不含堆栈、SQL、类名。
- **业务异常**：`BizException(code, message, httpStatus)`，由全局 `@RestControllerAdvice` 转壳；`message` 为可直接展示的中文文案。
- **系统异常**：未捕获异常统一 500 `COMMON_INTERNAL_ERROR`，`message` 固定“系统繁忙，请稍后重试”，详情只进日志与 `traceId`。
- **上游错误**：AI 502/504、微信 502 转换为本域 code；不把上游原文、endpoint、Key 返回客户端。
- **限流**：429 必须带 `Retry-After`（秒，整数），同时返回业务 code（`COMMON_RATE_LIMITED`、`AI_QUOTA_EXCEEDED`、`AUTH_ACCOUNT_LOCKED`）。
- **traceId**：所有响应（含二进制接口、SSE 首帧头、错误体）都带 `traceId`/`X-Trace-Id`；日志以其串联，禁止打印 Token、密码、openid 明文、`session_key`。
- **降级**：看板统计异常返回 200 + 空值/0；通知推送失败不影响落库；缓存失效失败返回成功并由 TTL 兜底。
- **禁止**：同语义跨模块返回不同 HTTP；200 包裹业务失败；用 401 代替 403。

## 10. 版本与废弃
- `/v1` 表示“路由与语义稳定版”；路径版本只在**不兼容**变更时递增，日常迭代在 v1 内演进。
- **字段只增不删**：新增可选字段不升版本；删字段、改类型、改语义、改默认值、收紧校验均不兼容，走第 11 节流程并评估 `/v2`。
- 枚举只增不改：新增值算兼容，客户端须容忍未知值；删除/重命名不兼容。
- 废弃方式（**不引入新路由**）：响应头 `Deprecation: true`、`Sunset: <HTTP-date>`、`Link: <文档地址>; rel="deprecation"`；本文与模块文档标注“废弃”并给出替代；至少保留一个发布周期（≥90 天），移除即升 `/v2`。
- 公告写入 00 变更记录与 06 开发计划；不通过“悄悄改语义”迁移。模块文档头部必须引用同一契约版本号。
