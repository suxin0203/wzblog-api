## 3. 认证与权限契约

### 3.1 鉴权方式

- 请求头：`Authorization: Bearer <accessToken>`。
- Access Token：JWT HS256，15 分钟；claims：`sub`（用户 ID 字符串）、`role`、`jti`、`iss=wzblog`、`aud=wzblog-web`、`iat`、`exp`；不放昵称/邮箱。
- Refresh Token：32 字节随机值 Base64URL，14 天；库中只存 SHA-256；每次登录生成 `family_id`，刷新即轮换。
- 旧 Refresh Token 再次出现 → 吊销整个 family（判定为泄露）。
- 登出：吊销当前 family + access 的 `jti` 进 Redis 黑名单（TTL = 剩余有效期）；`logout-all` 吊销该用户全部 family。
- 每个受保护请求回库校验用户存在且 `status=ACTIVE`（本项目规模可接受；后续可加 Redis 缓存）。
- 密码：BCrypt，强度 10；兼容旧哈希 `$2b$`。
- 角色：`USER` < `EDITOR` < `ADMIN`。`EDITOR` 可管理全部内容与审核，不能管用户/积分/配置；`ADMIN` 拥有全部权限。
- 资源归属：文章作者可编辑自己的文章；`EDITOR/ADMIN` 可编辑全部。订单、积分流水、会话只能看自己的（ADMIN 除外）。

### 3.2 权限标记（文档统一用词）

| 标记 | 含义 |
|---|---|
| `PUBLIC` | 无需登录 |
| `OPTIONAL` | 可选登录；登录后返回个性化字段 |
| `USER` | 任意已登录用户 |
| `EDITOR` | EDITOR 或 ADMIN |
| `ADMIN` | 仅 ADMIN |
| `OWNER` | 已登录且是资源所有者（ADMIN 可越过） |

## 5. 统一响应、错误码与分页

### 5.1 响应体

```json
{ "code": "OK", "message": "success", "data": {}, "traceId": "0199..." }
```

- `code` 为**字符串**业务码；成功固定 `OK`。
- 失败时 `data` 为 `null`；参数校验失败时 `data = { "errors": { "字段": "原因" } }`。
- `traceId` 每次请求都返回；同时写入响应头 `X-Trace-Id`。
- 所有 `BIGINT` ID 在 JSON 中为**字符串**（防 JS 精度丢失）。
- **二进制接口例外**：`GET /auth/qr/sessions/{sceneId}/code` 返回 `image/png`，不走统一响应壳；失败时仍返回 JSON 错误体。
- **幂等头**：`POST /points/orders` 必须携带 `Idempotency-Key`（8~64 位可见 ASCII，24 小时内同一用户唯一）；评论/留言可选携带。缺失或重复但请求体不一致时返回 409 `COMMON_IDEMPOTENCY_CONFLICT`。
- **SSE**：`/ai/chat/stream` 与 `/notifications/stream` 使用 `fetch` 流式读取（需要 `Authorization` 头）；不使用浏览器原生 `EventSource`。

### 5.2 HTTP 状态映射

| 场景 | HTTP | code 示例 |
|---|---|---|
| 成功读/更新 | 200 | `OK` |
| 创建成功 | 201 | `OK` |
| 参数/格式错误 | 400 | `COMMON_VALIDATION_ERROR` |
| 未登录（无凭证）/令牌无效/令牌过期 | 401 | `AUTH_UNAUTHORIZED` / `AUTH_TOKEN_INVALID` / `AUTH_TOKEN_EXPIRED` |
| 无权限/账号停用 | 403 | `AUTH_FORBIDDEN` / `AUTH_ACCOUNT_DISABLED` |
| 资源不存在 | 404 | `COMMON_NOT_FOUND` |
| 资源已过期/已消费（二维码、ticket、重置令牌） | 410 | `WECHAT_QR_EXPIRED` / `AUTH_RESET_TOKEN_EXPIRED` |
| 唯一冲突/状态不允许 | 409 | `ARTICLE_SLUG_CONFLICT` / `ORDER_STATE_INVALID` |
| 业务规则拒绝 | 422 | `POINTS_INSUFFICIENT` |
| 限流 | 429 | `COMMON_RATE_LIMITED`（带 `Retry-After`） |
| 上游返回错误 | 502 | `AI_UPSTREAM_ERROR` |
| 功能关闭/服务不可用 | 503 | `AI_DISABLED` |
| 上游超时 | 504 | `AI_UPSTREAM_TIMEOUT` |
| 系统异常 | 500 | `COMMON_INTERNAL_ERROR` |

### 5.3 错误码命名

`{模块}_{原因}`，全大写，蛇形；模块前缀固定：
`COMMON_`、`AUTH_`、`USER_`、`ARTICLE_`、`CATEGORY_`、`TAG_`、`COMMENT_`、`REACTION_`、`GUESTBOOK_`、`NOTIFY_`、`POINTS_`、`GOODS_`、`TITLE_`、`ORDER_`、`FILE_`、`AI_`、`CONFIG_`、`WECHAT_`。
每个错误码必须在接口契约中登记，禁止模块自造未登记代码。

### 5.4 分页

- 偏移分页：`page`（默认 1，最小 1）、`pageSize`（默认 20，最大 100）；响应：
  `{ list, total, page, pageSize, hasNext }`。
- 游标分页：`cursor`（不透明 Base64URL）、`size`（默认 20，最大 50）；响应：
  `{ list, nextCursor, hasNext }`。
- 列表永不为 `null`；无数据返回 `[]`。

### 5.5 时间与数字

- 入参时间：ISO-8601，必须带时区（推荐 `Z`）。
- 出参时间：ISO-8601 UTC，例如 `2026-10-24T04:00:00.000Z`。
- 统计与积分日上限的业务日：`Asia/Shanghai`（UTC+8）。
- 积分、金额、计数一律整数；禁止浮点。
- 小数比例（如阅读进度）用 0~1 的 `double`，仅用于展示。

### 6.2 文章状态规则

- `DRAFT`：仅作者/EDITOR/ADMIN 可见，不进入任何公开列表。
- `PUBLISHED`：满足 `visibility=PUBLIC` 才进入公开列表；`UNLISTED` 可直链访问但不进列表/搜索；`PRIVATE` 仅作者/管理员。
- `ARCHIVED`：下架；公开详情返回 404；作者/管理员仍可查看与恢复发布。
- 软删除：`deleted_at IS NOT NULL`；公开查询一律排除；`restore` 清空 `deleted_at`，保留原 `status`。
- 置顶：仅 `PUBLISHED` 可置顶；`is_pinned` 与 `status` 独立。
- slug：创建时可传（需匹配 `^[a-z0-9]+(?:-[a-z0-9]+)*$`，3~180 字符）；未传则用标题 ASCII 词生成，失败用 `post-{8位随机}`；发布后不可修改。

### 6.3 评论树规则

- 仅两级：根评论 `root_id = NULL AND parent_id = NULL`；回复的 `root_id` 指向根评论，`parent_id` 指向被回复评论。
- 回复的回复仍挂在同一 `root_id` 下，`reply_to_user_id` 记录被回复人。
- 删除父评论：写 `deleted_at`，保留子评论；前台展示「该评论已删除」。
- 仅 `APPROVED` 对公众可见；作者本人可见自己的 `PENDING`。
- 敏感词：命中后替换为 `*` 并置 `PENDING`；是否强制审核由配置 `comment.audit_enabled` 控制（默认 true）。

### 6.4 订单状态机

| 当前 | 允许的下一状态 | 触发者 |
|---|---|---|
| `PENDING` | `APPROVED` / `REJECTED` / `CANCELLED` | ADMIN 审核；用户取消 |
| `APPROVED` | `SHIPPED` / `CANCELLED` | ADMIN 发货；用户/管理员取消 |
| `SHIPPED` | `COMPLETED` | 用户确认或 ADMIN；7 天自动确认（可选） |
| `COMPLETED` | — | 终态 |
| `CANCELLED` | — | 终态（退积分 + 回补库存） |
| `REJECTED` | — | 终态（退积分 + 回补库存） |

- 所有变更用条件更新 `WHERE status = :from`，影响行数 0 → `ORDER_STATE_INVALID`（409）。
- `TITLE` 类商品在 `APPROVED` 时授予称号；`PHYSICAL` 在 `SHIPPED` 时填写物流。

## 9. 跨模块事件与允许的调用

### 9.1 领域事件（事务提交后异步处理，监听器必须幂等）

| 事件 | 发布方 | 订阅方 | 载荷 | 幂等键/语义 |
|---|---|---|---|---|
| `UserLoggedInEvent` | M1 | M4 | userId, loginAt, ip, firstLoginOfDay | `login:{userId}:{businessDate}` |
| `ArticlePublishedEvent` | M2 | M4 | articleId, authorId, title, publishedAt | `publish:{articleId}` |
| `ArticleDeletedEvent` | M2 | M4 | articleId, authorId | 反向流水 `article_delete:{articleId}` |
| `CommentApprovedEvent` | M3 | M4 | commentId, articleId, commenterId, articleTitle | `comment_approved:{commentId}` |
| `CommentRemovedEvent` | M3 | M4 | commentId, articleId, commenterId | 反向流水 `comment_removed:{commentId}` |
| `ReactionToggledEvent` | M3 | M4 | articleId, authorId, actorId, type, active | `like:{articleId}:{actorId}` / `unlike:{articleId}:{actorId}` |
| `OrderStatusChangedEvent` | M4 | M3 | orderId, orderNo, userId, fromStatus, toStatus | 通知去重 `order:{orderNo}:{toStatus}` |
| `PointsAdjustedEvent` | M4 | M3 | ledgerId, userId, amount, balanceAfter, reason | 通知去重 `points:{ledgerId}` |

规则：
- 发布使用 `ApplicationEventPublisher`，监听默认 `@TransactionalEventListener(AFTER_COMMIT)`；监听器异常不得影响主事务。
- 积分类事件必须由 M4 统一落账，其他模块不得直接写 `points_ledger`。
- 通知类事件失败可接受丢失；要求必达时升级 outbox + MQ（P1 之后再评估）。
- 事件类放在各模块 `domain.event` 包；跨模块只允许引用事件类与只读查询接口，不允许引用对方 Entity/Mapper。

### 9.2 允许的同步跨模块调用

| 调用方 | 被调用方 | 接口 | 用途 |
|---|---|---|---|
| M2/M1/M4/M7 | M5 | `FileAppService#claimByKey(objectKey, ownerId, bizType)` / `#releaseByKey(objectKey)` | 文件引用计数（同步，返回 fileId；不存在/非本人则抛业务异常） |
| M2 | M1 | `UserQueryService#getBriefs(ids)` | 文章列表/详情补充作者昵称与头像 |
| M8 | M1 | `WechatIdentityService#loginOrCreateByWechat` / `#registerAndBindWechat` / `#bindWechat` | 微信身份创建/绑定；M8 不直接读写 `users` 表 |
| M6 | M2 | `ArticleQueryService` 只读方法 | AI 工具查询公开文章 |
| M3 | M2 | `ArticleQueryService#getBrief` / `#getBriefs(ids)`；`ArticleCounterService#increment` / `#decrement` | 评论/点赞前校验文章状态与作者；同步维护文章计数 |
| M7 | M2 | `ArticleStatsService#drainDailyViews(date)` | 原子读取并删除 Redis 当日阅读计数（Lua）；M7 立即累加落库 |
| M3 | M1 | `UserQueryService#getBrief(userId)` / `#getBriefs(ids)` | 通知列表补充触发人昵称/头像 |
| M1 | M0 | `shared.profile.TitleLookup`（M4 提供实现） | 用户资料展示当前称号 |
| 各模块 | M0 | `SiteConfigService` | 读取站点配置与敏感词（缓存） |

| M8 | M1 | `AuthAppService#issueTokens(userId)` / `#revokeAll(userId)` | 登录成功签发/失效 Token |
| M3/M4 | M7（共享组件） | `AuditRecorder#record(...)` | 管理操作审计（写在 `shared.audit`） |

> 除上表外，跨模块只能通过事件解耦。模块内部的 Mapper 不得被其他模块注入。
>
> **只读分析例外**：M7 的看板与统计允许使用自有的 `AnalyticsMapper` 对多张业务表做**只读** SQL（不写、不加锁、不参与业务事务），用于避免跨模块 N 次调用。这是唯一的跨表读取例外，必须在 M7 文档中列明所读表与 SQL 口径。
