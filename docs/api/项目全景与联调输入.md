### A2. 后端启动

- 命令：`./scripts/run.sh`，内容即 `mvn spring-boot:run -Dspring-boot.run.profiles=local`（`scripts/run.sh:6`）。
- 端口：**8021**（`application.yml:2` `port: ${SERVER_PORT:8021}`）。**只有 local 一个 profile**，无 dev/test 区分；CI 测试用 Testcontainers 起真容器，不依赖 profile。
- 验证码开关：`WZBLOG_CAPTCHA_ENABLED=false` 可关闭图形验证码便于自动化（`application.yml:102`，默认 true）。
- 中间件：**MySQL 8.0**（连接串 `jdbc:mysql://${DB_HOST:127.0.0.1}:${DB_PORT:3306}/${DB_NAME:wzblog}...serverTimezone=UTC`，`application.yml:16`）+ **Redis 7**（DB 1，`application.yml:28`）。密钥来自根目录 `.env`（`spring.config.import: optional:file:./.env`）。
- 冒烟：`GET http://localhost:8021/api/v1/ping` → `{"code":"OK","message":"success","data":{"status":"pong",...}}`。

### A3. 前端启动

- 命令：`npm run dev`（`package.json scripts.dev = "vite"`）；构建 `npm run build`（含 `vue-tsc --noEmit` 类型检查）；类型检查单独 `npm run type-check`。
- 端口：**5173**（`vite.config.ts` `server.port: 5173`）。
- 代理：`vite.config.ts` `server.proxy['/api'] → http://localhost:8021`（changeOrigin），前端 `.env.development`：
  ```ini
  VITE_API_BASE_URL=/api/v1
  VITE_MEDIA_BASE_URL=http://localhost:8021/media
  ```

### A4. Docker / 初始化 SQL / 测试库

- `docker-compose.yml`：app + `mysql:8.0`（UTC 时区、utf8mb4）+ `redis:7-alpine`；`docker compose --profile observability up -d` 追加 Prometheus/Grafana；密钥全部 `${...:?set in .env}`。
- 建表：**Flyway 自动**跑 `src/main/resources/db/migration/V1__schema.sql`（**32 张表**）+ `V2__seed.sql`（种子分类），应用启动即完成，无需手动执行。
- 调试数据：`db/debug-data.sql` **一次性、非幂等**，填满 32 表；调试账号（密码统一 `Passw0rd1`）：`debug_admin`(ADMIN)、`debug_editor`(EDITOR)、`debug_reader`/`debug_guest`/`debug_newbie`/`debug_coder`(USER)、`debug_disabled`(DISABLED)、`deleted_1008`(已注销)。

### A5. monorepo / CI

- 非 monorepo。后端有 CI：`.github/workflows/` 三段（`# CI 三段：build（编译）→ test（Testcontainers 集成测试）→ package（打包并归档 jar）`），push 到 `master`/`feat/**` 或 PR 触发，Java 21 temurin。
- **前端无 git 仓库、无 CI**——编排 Agent 开工前建议先 `git init` 建基线，否则无法回滚。

### B3. 统一响应体与分页

```java
// common/api/Result.java
public record Result<T>(String code, String message, T data, String traceId) {}
// common/api/PageResult.java（偏移分页）
public record PageResult<T>(List<T> list, long total, int page, int pageSize, boolean hasNext) {}
// common/api/CursorPage.java（游标分页）
public record CursorPage<T>(List<T> list, String nextCursor, boolean hasNext) {}
```

- 成功 `code="OK"`，HTTP **一律 200**（v1.6.1 裁决并已整改验收，无 201）；失败 `data=null`；仅参数校验失败 `data={"errors":{"字段":"原因"}}`。
- 偏移分页参数 `page`(默认1)/`pageSize`(默认20,最大100)，越界 **400**（已整改）；游标分页 `cursor`/`size`(默认20,最大50)。

### B4. 错误码

- 唯一目录：`common/error/ErrorCode.java`，**105 个**（含 OK），命名 `{模块}_{原因}`，18 个前缀（COMMON_/AUTH_/USER_/ARTICLE_/CATEGORY_/TAG_/COMMENT_/REACTION_/GUESTBOOK_/NOTIFY_/POINTS_/GOODS_/TITLE_/ORDER_/FILE_/AI_/WECHAT_）。
- HTTP 映射固定：400 参数/400 文件类、401 凭证、403 权限、404 不存在（隐藏资源也 404）、409 冲突/状态、410 过期凭证、422 业务拒绝、429 限流（带 `Retry-After`）、500/502/503/504。全表见《接口对接文档.md》附录 A 与 docs/04 §1.5/§7。

### B5. 认证

- JWT HS256，`Authorization: Bearer <accessToken>`，15 分钟（`application.yml:99` `access-ttl: 15m`）；refresh 14 天**轮换制**（复用作废 refresh → 401 `AUTH_REFRESH_REUSED` 吊销全家簇）。
- 无 Session、无 Cookie；CORS 开发期全放开。
- 免鉴权清单（`config/SecurityConfig.java:35-93` PUBLIC_* 常量）：ping/actuator/swagger、`/api/v1/auth/captcha|register|login|refresh|password/forgot/**`、`GET /api/v1/articles**`、categories/tags、banners/friend-links/public/configs、points/goods、titles、`/api/v1/users/*/profile`、AI 游客通道（chat/stream、quota 等，用 `X-AI-Session-Token` 自校验）、`/users/*/me` 等 OPTIONS。权限链：`.requestMatchers("/api/v1/admin/users/**").hasRole("ADMIN")` → `/api/v1/admin/**` hasAnyRole(EDITOR,ADMIN) → anyRequest().authenticated()。

### B6. 字段命名与时间

- 全部 **camelCase**（唯一例外：旧协议兼容层 snake_case，§20，勿接）。ID 一律字符串（VO 逐字段 `@JsonSerialize(using = ToStringSerializer.class) Long id`；已知例外见附录 B-1：interaction 包 AuthorVO.userId 是 number）。
- 时间：出参 **ISO-8601 UTC**（`config/JacksonConfig.java`：`timeZone(UTC)` + 禁用 WRITE_DATES_AS_TIMESTAMPS），秒或毫秒精度并存；入参须带时区。

### B7. 枚举与状态机

- 契约 schema 内建 enum 14 处（visibility、role、status、type、bizType、toStatus 等），生成 TS 时直接得联合类型。

## D. 前端现状（wzblog-frontend）

### D1. 结构与组织

见 A1。路由：`src/router/index.ts` + `routes/`（portal/admin 分区）+ `guards.ts`；状态管理 Pinia（`src/store/modules/`，user 模块持 token 与 /users/me 资料）；请求层 16 个 api 模块按后端模块一一对应。

### D2. API 请求层（已按契约实现）

`src/utils/request.ts`（axios）：统一前缀 `VITE_API_BASE_URL`；请求拦截带 Bearer；响应拦截解析壳——`code === 'OK'（HTTP 2xx）→ 直接返回 data`；401 处理**仅** `AUTH_TOKEN_EXPIRED` 时用 refreshToken 静默续期并重放（并发单飞合并），其余 401 清凭据跳登录；`ApiError` 携带 `code/data/httpStatus/traceId/errors/retryAfter`。

SSE：`src/utils/sse.ts` 已实现 fetch 版通用客户端（支持 POST/GET、`Last-Event-ID` 续传、忽略 `: ping`），**AI 打字机/思考步骤条与通知流的 UI 消费待做**（任务单 docs/api/AI前端体验优化任务单.md）。

### D3. 类型定义

**手写**，非 OpenAPI 生成（package.json 无 openapi-typescript 等依赖）。`src/types/*.ts` 15 个文件，头部注明对齐的后端类：

```ts
// types/article.ts
/** 可见性（后端 ArticleVisibility 枚举） */
export type ArticleVisibility = 'PUBLIC' | 'PRIVATE' | 'UNLISTED'
export type ArticleStatus = 'DRAFT' | 'PUBLISHED' | 'ARCHIVED'
export interface ArticleAuthor { id: string; nickname: string; avatarKey: string | null }
```

抽查与后端枚举/字段一致；ID 已按 string 建模。未做全量 any 扫描——建议编排 Agent 跑一次 `npm run type-check`（vue-tsc）作为基线。

### D4. 登录态与守卫

`src/router/guards.ts`：`requiresAuth` 无凭证 → `/login?redirect=...`（`safeRedirect` 防开放重定向）；`roles` 角色不匹配提示并回首页；F5 后 Pinia 清空，守卫内先拉 `/users/me`（token 过期由 axios 静默刷新兜底）；已登录访问 login/register 回跳。

### D5. 前端已知问题

- **不是 git 仓库**（`git rev-parse` → fatal: not a git repository）——无历史、无回滚、无 CI，最高优先风险。
- `docs/` 只有 DEPLOY.md；代码注释引用的"契约 docs/api/接口对接文档.md"在前端仓库**不存在**（在后端仓库），编排时用绝对路径引用。

### E2. 历史易错点（全部有实锤记录，验收时重点盯）

| 坑 | 实锤 |
|---|---|
| ID 字符串化 | 线上 "2005"，springdoc 推导 int64（附录 B-5）；interaction author.userId 例外是 number（B-1） |
| 成功状态码 | 曾 201/200 并存，已统一 200（commit aadc98b） |
| 分页参数 | 参数名是 `pageSize` 不是 `size`；offset 越界现在 400（曾静默收敛）；cursor 用 `size` |
| 时间 | 双精度 ISO-8601 UTC（秒/毫秒并存），前端解析需兼容 |
| 404 语义 | 隐藏资源统一 404 ≠ 接口错；公开文章越权写才是 403 |
| 401 处理 | 只对 AUTH_TOKEN_EXPIRED 静默刷新重放 |
| SSE | 禁 EventSource；tool 事件 params 可选；通知流 Last-Event-ID、每用户 3 连接上限 |
| 幂等 | 下单必带 Idempotency-Key；评论/留言没有幂等保护须防抖 |
| banner 500 | 缺 imageKey 返 500（B-9），前端先自校验 |

## F. 给编排 Agent 的约束

### F1. 只读（禁止修改）

- `docs/api/**`（契约产物是生成文件 + 已冻结契约）、`docs/00~15` 编号文档、`docs/modules/**`（母契约/模块文档）

- 后端 `common/api`、`common/error`（响应壳/错误码是契约本体）

### F2. 允许修改

- 后端：`src/main/java/com/wzblog/modules/**`（业务包）、`src/test/**`
- 前端：`wzblog-frontend/src/**`、`vite.config.ts`、`.env.*`
- 例外：改动若涉及响应壳/错误码/路由结构 → 属契约变更，停下走 B9 流程

### F3. 提交与回滚

- 后端：每完成一个任务块 commit 一次（现有惯例：`feat(ai): …` / `refactor(api): …` 风格，见 git log），工作分支 `feat/**`（CI 会跑）。
- 前端：**先 `git init` + 初始 commit 建基线**，之后同样每任务块一 commit。
- 回滚单位 = commit；禁止 force push。

### F4. 必须停下报告的判定（三者任一）

1. 编译失败（后端 `mvn compile` / 前端 `npm run type-check`）且 15 分钟内无法定位；
2. 测试失败（后端 122 用例任何一条变红）；
3. **实测行为与 `docs/api/openapi.yaml` 不一致**——按附录 B 格式登记差异上报，**禁止**在前端写兼容代码掩盖或私自改契约。

### F5. 最终产出（四件）

1. **联调通过清单**：接口级（方法+路径+验证方式+样例比对结果）+ 页面级（按 E1 队列）
2. **缺陷清单**：按附录 B 表格格式（差异/现状/契约要求/影响/建议）
3. **测试报告**：E1 逐队列的执行结果与环境记录
4. **修复 diff 汇总**：每轮 commit 的变更说明（破坏性标注）
