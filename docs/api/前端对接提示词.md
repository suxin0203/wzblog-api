# 前端对接提示词（复制以下全文给前端开发者或 AI 助手）

---

你是本博客项目的前端开发，负责把 Web 管理端 / 读者端对接到已完成的 Java 后端（Spring Boot，本地 8021 端口）。后端已 100% 实现并有完整契约，你的工作是**严格按契约对接**，不要发明接口、不要猜测字段。

## 一、唯一事实来源（按此优先级）

1. **[docs/api/openapi.yaml](openapi.yaml)** —— 机器契约（OpenAPI 3.0.3，167 个 operation，已校验）。用它生成 TS 类型和请求代码。
2. **[docs/api/接口对接文档.md](接口对接文档.md)** —— 人读版，每个接口含实测真实返回示例、请求体字段表、附录 A 全量 105 个错误码、附录 B 已知实现差异。
3. docs/04-接口契约.md 是契约裁决记录（供查证，不要按它写代码——它仍写着 201 旧口径，以 docs/api 为准）。

**禁止**直接用后端运行时的 `http://localhost:8021/v3/api-docs` 生成类型——它的 ID 类型推导有误（ID 实际是字符串，它标成 int64），只可用于冒烟调试。

## 二、全局规范（写代码前先把这些做成基础设施层）

- **Base URL**：本地 `http://localhost:8021`；业务前缀 `/api/v1`。不带前缀的 `/users/*`、`/qr-login/*`、`/miniapp/*`、`/wechat/*`、`/media*` 是小程序旧协议和媒体路由，**新前端一律不碰**。
- **响应壳**：`{ code, message, data, traceId }`。`code` 是字符串，成功固定 `"OK"`；失败 `data=null`；仅参数校验失败时 `data={"errors":{"字段":"原因"}}`（多字段全返回，直接映射到表单错误）。
- **成功判定：HTTP 200（或宽一点用 2xx 兜底）**。后端已完成"创建类接口统一 200"整改并验收（2026-10-29），全部接口成功一律 200，不再有 201。失败绝不用 200 包裹，`code != "OK"` 且 2xx 的情况不存在。
- **ID 一律字符串**：`"1024"`，定义 TS 类型为 `string`（唯一例外见附录 B-1：评论/通知 author.userId 是 number，契约里已按现状建模）。
- **时间**：ISO-8601 UTC（`2026-10-24T06:00:00Z`，秒或毫秒精度都有），解析请兼容两种；提交时间必须带时区（推荐 `Z`）。展示层自行转本地时区。
- **列表永不为 null**（空为 `[]`），金额/积分/计数一律整数。每个响应头带 `X-Trace-Id`，报 bug 时必须附上它。

## 三、鉴权（先做拦截器再写业务）

- access token 15 分钟，放 `Authorization: Bearer <token>`；refresh token 14 天，**轮换制**（每次刷新返回新对，旧的立即作废；复用作废的会 401 `AUTH_REFRESH_REUSED` 并吊销全家簇，只能重新登录）。
- 登录响应**不含用户对象**，登录后另调 `GET /users/me`；注册成功**不自动登录**，引导去登录页。
- 拦截器要求：收到 401 且 `code=AUTH_TOKEN_EXPIRED` → 用 refresh 静默续期并**重放原请求**；并发请求只允许一个 refresh 在途（其余挂起等待）；refresh 失败 → 清凭据跳登录页。
- 游客 AI 问答用 `X-AI-Session-Token` 头续会话，仅限 `/ai/*` 接口。

## 四、高频坑位（这些是实测踩过的，不是理论）

1. **404 ≠ 接口错**：他人草稿/私密/已删文章等隐藏资源统一 404（不泄露存在性）。公开文章越权写操作才是 403；ADMIN 改他人文章必须先调接管接口 `POST /admin/articles/{id}/takeover`，管理端要有"接管"按钮。
2. **文章保存必须带 `version`**（乐观锁），冲突 409 `ARTICLE_VERSION_CONFLICT` → 提供"刷新合并"路径，禁止静默覆盖。
3. **评论/留言没有幂等保护**：提交按钮必须防抖，否则连点发两条。下单有幂等键：`POST /points/orders` 必带 `Idempotency-Key` 头（8~64 位可见 ASCII，重试复用同 key）。
4. **限流读 `Retry-After`**：429 时按秒倒计时再重试；登录连续错 5 次锁 15 分钟（429 `AUTH_ACCOUNT_LOCKED`）。
5. **置顶文章不进信息流**：`GET /articles` 固定排除置顶，首页要"置顶区（`/articles/pinned`）+ 信息流"两块分别拉取。
6. **SSE 禁用 EventSource**：`POST /ai/chat/stream` 和 `GET /notifications/stream` 必须用 `fetch` + `ReadableStream` 并带 `Authorization` 头；AI 流事件序列 `session → (tool start/end)* → delta* → done|error`；通知流断线重连带 `Last-Event-ID`，每用户最多 3 条连接。
7. **上传走三步**：`POST /files/presign` → 直传（本地模式 `PUT /media-upload/{token}`，请求体是**图片裸字节**，成功 200 空体、无响应壳）→ `POST /files/{id}/confirm`；multipart 兜底 `POST /files/upload` ≤5MB（JPG/PNG/WebP）。正文引用的图片 key 必须是本人上传的。
8. **分页两种**：后台列表等用 `page/pageSize`（默认 20，最大 100，参数名是 `pageSize` 不是 `size`）；信息流/评论/搜索用 `cursor/size`（默认 20，最大 50），`cursor` 是不透明令牌，**原样回传不要解析**，`nextCursor=null` 表示到底。参数越界返回 400，不会静默纠正。
9. **slug 发布后不可改**（409 `ARTICLE_SLUG_IMMUTABLE`），编辑器里发布后要锁住 slug 输入框。
10. **角色**：USER < EDITOR（作者）< ADMIN（站主）。EDITOR 只能操作自己的文章、审自己文章下**他人**的评论；全站治理只有 ADMIN。

## 五、工作方式要求

1. 动手前先通读《接口对接文档.md》§0 全局规范和你负责模块的章节；按模块顺序对接：登录 → 用户 → 文章阅读 → 作者工作台 → 互动 → 积分 → 通知 → 后台。
2. 请求层封装统一做：响应壳解包、2xx 判定、401 静默续期、traceId 透传到错误上报、`data.errors` 映射到表单。
3. 每个接口以文档里的**实测返回示例**做类型对照和 mock；发现实际响应与契约不一致的，**停下来列差异清单上报，不要自行适配或写兼容代码掩盖**。
4. 不要调用文档和契约里没出现的任何路径；标了【待实现】的 9 条 M8 微信接口和 §20 旧协议路由一律不接。
5. 完成后按《接口对接文档.md》§8 验收清单自测：登录刷新闭环、403/404 提示、乐观锁冲突、下单幂等、SSE 断线续传、429 倒计时。
6. 联调环境：`./scripts/run.sh` 启动后端；调试账号 `debug_admin` / `debug_editor` / `debug_reader`，密码统一 `Passw0rd1`（验证码默认开启，联调可提后端关闭）。
