## 1. 裁决内容

v1.6.1 起，本契约**所有接口成功一律返回 HTTP 200**（响应壳 `{code:"OK",...}` 不变）。废除 docs/04 §1.3 "创建成功用 201" 的旧口径（该口径已与裁决冲突，母契约文档由项目所有者另行更新）。

理由：统一 200 后，HTTP 状态码层只表达"成功/失败类别"，业务语义全部收敛到响应壳 `code` 字段，前端无需为创建类接口维护 201 分支，接口风格更一致。

## 2. 整改清单（10 处）

- `ResponseEntity.status(HttpStatus.CREATED).body(Result.ok(x))` / `ResponseEntity.status(201).body(Result.ok(x))` → 改为 `ResponseEntity.ok(Result.ok(x))`；

## 3. 终审补充整改项（v2 新增，2026-10-29 全量审计发现）

### 3.1 offset 分页参数补校验（⚠️ 与 cursor 分页不对称）

**现状**：cursor 分页已正确校验（`size=999` → 400 `COMMON_VALIDATION_ERROR`），但 offset 分页**静默收敛**不报错：

```
GET /api/v1/notifications?page=1&pageSize=999  → 200，pageSize 回显被收敛为 100
GET /api/v1/notifications?page=0&pageSize=5    → 200，page 回显被收敛为 1
GET /api/v1/notifications?page=-3&pageSize=5   → 200，page 回显被收敛为 1
```

**要求**：按契约 §5.1 冻结口径改为校验拒绝，**400 `COMMON_VALIDATION_ERROR`，不静默纠正**：
- `page < 1` → 400
- `pageSize < 1` 或 `pageSize > 100` → 400

**影响范围**：全部 offset 分页接口（`/notifications`、`/points/orders`、`/points/ledger`、`/me/articles`、`/admin/*` 所有列表）。建议在统一的分页参数解析处加一个校验方法一次性覆盖，勿逐接口散改。

### 3.2 看板 from/to 日期参数补校验

**现状**：`GET /api/v1/admin/dashboard/overview?from=2026-13-99` → 200（非法日期被忽略）。

**要求**：按契约 §5.4，`from`/`to` 必须是合法 `YYYY-MM-DD`，非法 → 400 `COMMON_VALIDATION_ERROR`（6 个看板接口同口径）。
