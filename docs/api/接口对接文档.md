## 0. 全局规范（必读）

| 项 | 值 |

### 0.2 统一响应壳

```json
{ "code": "OK", "message": "success", "data": { … }, "traceId": "d0bb5fb3ff974722bc70d6819c3ccb90" }
```

- `code` 是**字符串**：成功固定 `"OK"`（HTTP 200；v1.6.1 裁决创建/动作成功统一 200，废除 201）；失败时 HTTP 状态码表达语义，`data=null`。
- 仅**参数校验失败**（400）时 `data={"errors":{"字段":"原因"}}`，多字段全返回。实测样例：

```json
{
 "code": "COMMON_VALIDATION_ERROR",
 "message": "size 需在 1~50",
 "data": null,
 "traceId": "ab242c297f84464381041a22fe8f1b55"
}
```

- 401（无 token，实测）：

```json
{
 "code": "AUTH_UNAUTHORIZED",
 "message": "请先登录",
 "data": null,
 "traceId": "cb3039047356405ca2544d73c8744c16"
}
```

### 0.3 鉴权：双 Token

| Token | 有效期 | 传递 | 说明 |
|---|---|---|---|
| accessToken | 15 分钟（`expiresIn=900`） | `Authorization: Bearer <token>` | JWT；过期 401 `AUTH_TOKEN_EXPIRED` |
| refreshToken | 14 天 | 仅提交给 `POST /auth/refresh` | **轮换制**：每次刷新发新对、旧 refresh 作废；复用旧 refresh（401 `AUTH_REFRESH_REUSED`）触发全家簇吊销 |

- 登录响应**不含用户对象**，资料另调 `GET /users/me`。注册成功**不自动登录、不发 token**。
- 拦截器建议：401 且 `code=AUTH_TOKEN_EXPIRED` → 用 refresh 换新并重放原请求；并发只允许一个 refresh 在途；refresh 失败（401）→ 清凭据跳登录。
- 游客 AI 会话另用 `X-AI-Session-Token` 头（仅 `/ai/*` 相关接口）。
- 角色：`USER` < `EDITOR`（作者）< `ADMIN`（站主）。内容主权规则（改他人文章：公开 403 / 隐藏 404；ADMIN 改稿必须先接管）详见 §4。

### 0.4 数据口径

- **ID 一律字符串**：`"1024"`（⚠️ 现有例外见附录 B-1：评论/通知 author.userId 线上是数字）。
- **时间**：ISO-8601 UTC，秒或毫秒精度（`2026-10-24T06:00:00Z` / `…T15:50:51.405Z`），前端解析请兼容两种；入参必须带时区（推荐 `Z`）。
- **列表永不为 null**（空为 `[]`）；金额/积分/计数一律整数。
- 创建/动作成功统一返回 **200**（v1.6.1 裁决，废除 docs/04 此前的 201 口径；后端已完成整改并经 2026-10-29 复测验收，全部接口实测 200）。

### 0.5 分页

| 方式 | 请求参数 | 响应 | 适用 |
|---|---|---|---|
| 偏移分页 | `page`（默认 1）、`pageSize`（默认 20，最大 100） | `PageResult{list,total,page,pageSize,hasNext}` | 后台列表、我的文章、通知、订单、流水 |
| 游标分页 | `cursor`（首页不传）、`size`（默认 20，最大 50） | `CursorPage{list,nextCursor,hasNext}` | 信息流、评论、留言、我的点赞/收藏、AI 消息、搜索 |

- 参数越界（`page<1`、`pageSize>100` 等）→ 400，不静默纠正；`hasNext=false` 时 `nextCursor=null`。
- `cursor` 是不透明 Base64URL，原样回传，不要解析。

### 0.6 幂等与并发

- `POST /points/orders` **必带** `Idempotency-Key` 头（8~64 位可见 ASCII）：同键同体 → 200 + 原订单；缺失 → 400；同键不同体 → 409。
- **评论/留言没有幂等键保护**：docs/04 R056/R066 标"可选 Key"，但后端未实现该头（传了不生效，重复提交会发两条）。前端发评论/留言必须自行防抖（见附录 B-7）。
- 文章更新（PUT）**必带 `version`**（乐观锁）：冲突 409 `ARTICLE_VERSION_CONFLICT`，应提示刷新合并。

### 0.7 错误码速查

| HTTP | 典型 code | 前端动作 |
|---|---|---|
| 400 | `COMMON_VALIDATION_ERROR`、`*_INVALID` | 展示 data.errors 或 message |
| 401 | `AUTH_UNAUTHORIZED` / `AUTH_TOKEN_INVALID` / `AUTH_TOKEN_EXPIRED` | 引导登录 / 静默续期重放 |
| 403 | `AUTH_FORBIDDEN` / `AUTH_ACCOUNT_DISABLED` | 提示无权限，不要重试 |
| 404 | `*_NOT_FOUND` | **404 ≠ 接口错**（隐藏资源统一 404） |
| 409 | `*_CONFLICT` / `*_STATE_INVALID` / `ARTICLE_VERSION_CONFLICT` | 提示刷新后重试 |
| 410 | `*_EXPIRED` | 引导重新获取凭证 |
| 429 | `COMMON_RATE_LIMITED` / `AI_QUOTA_EXCEEDED` | 按 `Retry-After` 倒计时 |
| 503 | `AI_DISABLED` / `WECHAT_NOT_ENABLED` | 功能未开放 |

全量 105 个错误码见 **附录 A**；同一 code 只绑一个 HTTP。

### 0.8 SSE 约定

- 端点：`POST /ai/chat/stream`、`GET /notifications/stream`；`Content-Type: text/event-stream`。
- **必须 fetch + ReadableStream + Authorization 头**，禁用 EventSource、禁止 token 放 query。
- 帧格式 `event: <name>` + `data: <单行 JSON>`；每 15 秒 `: ping` 心跳。
- AI 五事件：`session` → (`tool` start/end)* → `delta`* → `done`；失败 `error` 收尾。通知流：`ready` → `notification`（带 `id:`，断线用 `Last-Event-ID` 续传）。实测样例见 §10/§16。

### 19.1 字段与行为（统一响应壳；错误码 `WECHAT_*` 14 个均已登记 error-codes.md）

| 接口 | 请求字段 | 响应 data |
|---|---|---|
| R139 login | `code`(必填 ≤128)、`nickname`(≤30 可选)、`avatarKey`(≤255 可选，格式校验) | `tokenType`/`accessToken`/`expiresIn`(900)/`refreshToken`/`refreshExpiresIn`/`user{id,username,nickname,avatarKey,role,status,openidBound}`；openid 不存在自动建号（source=WECHAT，随机用户名 `wx_`+12 位），停用 403 |
| R140 bind | `code`(必填) | `bound`/`user`；幂等：重复绑同一 openid `bound=true`；当前账号已绑其他 openid → 409 `WECHAT_ACCOUNT_ALREADY_BOUND` |
| R141 sessions | 无请求体字段 | `sceneId`(16 位 `[0-9A-Za-z]`)/`status=PENDING`/`expiresAt`；TTL 120s |
| R142 轮询 | — | `sceneId`/`status(PENDING\|CONFIRMED\|COMPLETED\|EXPIRED)`/`ticket`(仅 CONFIRMED，**不消费**)/`expiresAt`；限流 1 次/秒·scene+ip → 429 `COMMON_RATE_LIMITED` + `Retry-After` |
| R143 code | `env_version`?(query，release/trial/develop) | `image/png` 二进制（`no-store`；**响应壳显式例外**，失败仍 JSON：404 `WECHAT_QR_NOT_FOUND`/502 `WECHAT_API_ERROR`） |
| R144 confirm | `bindToken`?(43 位 Base64URL，**无登录态时必填**)、`userInfo`?(仅 R145 生效，此处忽略) | `sceneId`/`status=CONFIRMED`/`bindToken`(一次性 60s)/`bindTokenExpiresAt`；二者皆无 → 401 `AUTH_UNAUTHORIZED`；重复确认 → 409 `WECHAT_QR_ALREADY_CONFIRMED` |
| R145 register-and-confirm | `bindToken`(必填)、`username`(4~20 `^[A-Za-z0-9_]$`，同 M1)、`password`(8~64 可见 ASCII 且含字母数字，同 M1)、`nickname`?(≤30) | 同 R144 但 `bindToken=null`；建正式账号 source=QR；用户名冲突 409 `AUTH_USERNAME_TAKEN`（bindToken 不消费，可重试） |
| R146 bind-and-confirm | `bindToken`(必填) + `Authorization` 必带 | 同 R145；绑定目标恒为当前登录用户，不接收账号密码 |
| R147 exchange | `ticket`(必填 43 位) | 同 R139 的 TokenPair+user；GETDEL 一次性，重放 401 `WECHAT_TICKET_INVALID` |

**状态机**：`PENDING` →（R144/R145/R146 条件更新单胜）→ `CONFIRMED`（Redis 放 60s ticket）→（R147，GETDEL）→ `COMPLETED`；过期懒判定 + 每分钟清理置 `EXPIRED`（轮询返回 `EXPIRED`，确认尝试 410 `WECHAT_QR_EXPIRED`）。

**行为口径**（与 M8 设计/验收用例对齐）：
1. **轮询不签发 Token**（R142 只读）；PC 唯一取 Token 入口是 R147。
2. R144 JWT 路径把当前用户绑定 openid 写入会话 `temp_openid`；`bindToken` 替代路径以 `temp_openid` 登录/建号后确认。
3. R145/R146 允许在 `PENDING`/`CONFIRMED` 会话上**重确认**（M8 TC-026"会话仍 CONFIRMED 可重试"口径）：覆盖 `user_id`、作废旧 ticket、放新 ticket；`COMPLETED`/过期不可。
4. R145 顺序：校验 bindToken（不消费）→ M1 建号 → 消费 bindToken；无效 token 不产生任何账号。
5. openid 明文永不输出（仅 `openidBound` 布尔）；`session_key` 不落库不返回。
6. **模块关闭语义**（docs/16 §4）：provider=auto 且凭据缺失 → 微信功能一律 503 `WECHAT_NOT_ENABLED`（R141/R139/R147 等），密码登录不受影响；旧协议 `/wechat/openid/{code}` 按旧壳输出 HTTP 200 + `code:0` + `errcode:503`。本地/CI 确定性上游必须**显式** `provider=mock`。R143 的 `env_version` 白名单 release/trial/develop，非法取值回落默认配置。

> openapi.yaml：本节路由此前按 `x-status: pending` 建模，**待后端重启后由 `/v3/api-docs` 重新导出**（本轮先改本文，机器契约下次导出对齐）。

### 21.2 权限矩阵

## 3. 权限矩阵
| 标记 | 判定 | 能力边界 |
|---|---|---|
| `PUBLIC` | 不校验身份 | 只读公开资源或公共动作（登录/扫码/换票）；不得返回个人数据 |
| `OPTIONAL` | 有 Token 则解析，无则匿名 | 匿名返回公开字段；登录后追加 `liked`、本人 PENDING、游客会话等个性化字段 |
| `USER` | 任一 `ACTIVE` 用户 | 仅操作本人资源；跨用户 ID 按 404 处理，不泄露存在性 |
| `EDITOR` | `EDITOR` 或 `ADMIN` | 受邀作者：只能编辑自己的文章、发布/下架/删除自己的文章、审自己文章下**他人**的评论、AI 辅助自己的文章、文件预签名；不能管分类标签、置顶、留言板、全站评论、用户、积分、配置 |
| `ADMIN` | 仅 `ADMIN` | 站主：文章治理（软删/恢复/purge/置顶/接管）、分类标签、全站评论/留言板、用户、积分商城、订单、配置、轮播、友链、看板、审计、AI 后台、文件清理；也可作为作者写自己的文章 |
| `OWNER` | 已登录且为资源所有者 | 本人评论/留言/订单/文件/会话；`ADMIN` 可越过；他人资源按 404 |

**EDITOR 与 ADMIN 的差异（v1.6，A 方案）**：EDITOR 只能编辑自己的文章，不能编辑他人文章；可以审自己文章下他人的评论，但不能审自己写的评论；不能管分类标签、置顶、留言板、后台文章列表。ADMIN 拥有站点治理能力，但**改他人正文必须先接管**（`POST /admin/articles/{id}/takeover`），不做静默改稿。ADMIN 对 OWNER 资源的越过只适用于文件删除、会话等资源，不适用于文章正文。

**文章越权语义**：非作者访问已公开文章（`PUBLISHED + PUBLIC`）→ 403 `ARTICLE_FORBIDDEN`；草稿/PRIVATE/UNLISTED/ARCHIVED/已删 → 404 `ARTICLE_NOT_FOUND`，不泄露存在性。ADMIN 不豁免，必须先接管。

**文件引用的归属判定**：请求中新增/更换的图片，`files.uploader_id` 必须是业务资源所有者（如文章作者）或当前操作人，ADMIN 可越过；回滚修订等恢复服务端已存内容时 key 不来自请求，走 `claimRecordedByKey`，不校验上传者。文章软删不释放引用；purge 才释放。

**OWNER 判定规则**：一律用 JWT `sub` 与资源外键比对，**不接受** query/body 传入的 `userId` 作为归属依据；归属失败与不存在返回同一 404，仅“存在但角色不足”返回 403；文章写操作按上面的“文章越权语义”区分 403/404；归属校验在 `app` 层执行（路由注解之外的第二道）；`/users/{id}/profile` 为 PUBLIC 白名单读，不属 OWNER 语义。

### 21.4 请求公共规范（分页/游标/幂等/筛选）

## 5. 请求公共规范
### 5.1 分页
| 方式 | 参数 | 默认/上限 | 响应 | 适用 |
|---|---|---|---|---|
| 偏移 | `page`、`pageSize` | `page=1`；`pageSize=20`，最大 100 | `PageResult<T>` | 后台列表、`/me/articles`、通知、订单/流水 |
| 游标 | `cursor`、`size` | `size=20`，最大 50（搜索/后台另限） | `CursorResult<T>` | 信息流、评论、留言、我的点赞/收藏、AI 消息 |

- `page<1`、`pageSize`/`size` 越界 → 400 `COMMON_VALIDATION_ERROR`，不静默纠正。
- 同一接口不得同时接受 offset 与 cursor；前台信息流/搜索禁止 offset 深翻页。
### 5.2 游标编码
- `cursor` 为不透明 Base64URL（无填充），内容 `"{排序键}:{id}"`（如 `"{publishedAtEpochMs}:{id}"`）。
- 客户端原样回传，不得解析或拼装；非法/篡改 → 400 `COMMON_VALIDATION_ERROR`。
- 首页不传；`hasNext=false` 时 `nextCursor=null`；游标只保证同一排序口径下不重不漏。
### 5.3 排序白名单
| 接口 | 允许值 | 默认 |
|---|---|---|
| `/articles` | 固定 `publishedAt DESC, id DESC` | 不接收 `sort` |
| `/articles/top` | `type∈{view,like,favorite,comment}`，`limit≤10` | `view` |
| `/admin/articles` | `sort∈{updatedAt,createdAt,publishedAt}` | `updatedAt` |
| `/admin/dashboard/article-rank` | `metric∈{view,like,favorite}` | `view` |
| `/admin/banners`、`/admin/friend-links`、公开轮播/友链 | 固定 `sortOrder ASC, id ASC` | — |
| 其余列表 | 固定 `createdAt DESC, id DESC`（评论子级为 `ASC`） | — |

- 白名单外排序一律 400；不接受列名、SQL 片段、`orderBy` 透传。
### 5.4 筛选参数命名
- 统一 camelCase：`keyword`、`categoryId`、`tagId`、`authorId`、`status`、`visibility`、`deleted`、`userId`、`type`、`channel`、`bizType`、`metric`、`limit`、`from`、`to`。
- `keyword` ≤50；`year` 2000~2100、`month` 1~12 且必须与 `year` 成对。
- 时间筛选取 ISO-8601（默认左闭右开）；**唯一例外**：6 个看板接口的 `from`/`to` 为 `YYYY-MM-DD`（`Asia/Shanghai` 自然日、闭区间）。
- 枚举筛选传大写字符串，未知值 400；不传表示“全部”，不接受空串。
### 5.5 Idempotency-Key 与并发控制
- 格式 8~64 位可见 ASCII（`0x21~0x7E`），按“用户 + 键”24 小时内唯一。
- **必带**：`POST /points/orders`；缺失/非法 → 400 `COMMON_VALIDATION_ERROR`，不建单、不扣分。
- **可选**：`POST /articles/{articleId}/comments`、`POST /guestbook`；未带由限流兜底。
- 同键同体 → 返回首次结果（订单为 200 + 同一 `orderNo`），不重复扣减或扣库存；同键不同体 → 409 `COMMON_IDEMPOTENCY_CONFLICT`。
- 其余写接口不用幂等键，靠唯一键、条件更新与“状态设置”语义保证幂等。
- **`If-Match`/`ETag` 默认不使用**：仅文章更新用请求体 `version`（int 必填）做乐观锁，冲突 409 `ARTICLE_VERSION_CONFLICT`；其他资源不暴露版本号，不支持 HTTP 条件请求。
- 409 时客户端应重新拉取最新状态再决定是否重试，禁止自动无限重试。

### 21.8 版本管理与契约变更流程（R 编号约定）

## 10. 版本与废弃
- `/v1` 表示“路由与语义稳定版”；路径版本只在**不兼容**变更时递增，日常迭代在 v1 内演进。
- **字段只增不删**：新增可选字段不升版本；删字段、改类型、改语义、改默认值、收紧校验均不兼容，走第 11 节流程并评估 `/v2`。
- 枚举只增不改：新增值算兼容，客户端须容忍未知值；删除/重命名不兼容。
- 废弃方式（**不引入新路由**）：响应头 `Deprecation: true`、`Sunset: <HTTP-date>`、`Link: <文档地址>; rel="deprecation"`；本文与模块文档标注“废弃”并给出替代；至少保留一个发布周期（≥90 天），移除即升 `/v2`。
- 公告写入 00 变更记录与 06 开发计划；不通过“悄悄改语义”迁移。模块文档头部必须引用同一契约版本号。
