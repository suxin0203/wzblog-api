## 0. 全局规范（必读）

| 项 | 值 |

| 业务前缀 | `/api/v1`（例外：§20 旧协议与媒体路由不带前缀） |

| 响应头 | 每个响应带 `X-Trace-Id`；限流响应带 `Retry-After`（秒） |

### 0.2 统一响应壳

```json
{ "code": "OK", "message": "success", "data": { … }, "traceId": "d0bb5fb3ff974722bc70d6819c3ccb90" }
```

- `code` 是**字符串**：成功固定 `"OK"`（HTTP 200；v1.6.1 裁决创建/动作成功统一 200，废除 201）；失败时 HTTP 状态码表达语义，`data=null`。
- 仅**参数校验失败**（400）时 `data={"errors":{"字段":"原因"}}`，多字段全返回。实测样例：

```json
{
 "code": "COMMON_VALIDATION_ERROR",
 "message": "size 需在 1~50",
 "data": null,
 "traceId": "ab242c297f84464381041a22fe8f1b55"
}
```

- 401（无 token，实测）：

```json
{
 "code": "AUTH_UNAUTHORIZED",
 "message": "请先登录",
 "data": null,
 "traceId": "cb3039047356405ca2544d73c8744c16"
}
```

### 0.3 鉴权：双 Token

| Token | 有效期 | 传递 | 说明 |
|---|---|---|---|
| accessToken | 15 分钟（`expiresIn=900`） | `Authorization: Bearer <token>` | JWT；过期 401 `AUTH_TOKEN_EXPIRED` |
| refreshToken | 14 天 | 仅提交给 `POST /auth/refresh` | **轮换制**：每次刷新发新对、旧 refresh 作废；复用旧 refresh（401 `AUTH_REFRESH_REUSED`）触发全家簇吊销 |

- 登录响应**不含用户对象**，资料另调 `GET /users/me`。注册成功**不自动登录、不发 token**。
- 拦截器建议：401 且 `code=AUTH_TOKEN_EXPIRED` → 用 refresh 换新并重放原请求；并发只允许一个 refresh 在途；refresh 失败（401）→ 清凭据跳登录。
- 游客 AI 会话另用 `X-AI-Session-Token` 头（仅 `/ai/*` 相关接口）。
- 角色：`USER` < `EDITOR`（作者）< `ADMIN`（站主）。内容主权规则（改他人文章：公开 403 / 隐藏 404；ADMIN 改稿必须先接管）详见 §4。

### 0.4 数据口径

- **ID 一律字符串**：`"1024"`（⚠️ 现有例外见附录 B-1：评论/通知 author.userId 线上是数字）。
- **时间**：ISO-8601 UTC，秒或毫秒精度（`2026-10-24T06:00:00Z` / `…T15:50:51.405Z`），前端解析请兼容两种；入参必须带时区（推荐 `Z`）。
- **列表永不为 null**（空为 `[]`）；金额/积分/计数一律整数。
- 创建/动作成功统一返回 **200**（v1.6.1 裁决，废除 docs/04 此前的 201 口径；后端已完成整改并经 2026-10-29 复测验收，全部接口实测 200）。

### 0.5 分页

| 方式 | 请求参数 | 响应 | 适用 |
|---|---|---|---|
| 偏移分页 | `page`（默认 1）、`pageSize`（默认 20，最大 100） | `PageResult{list,total,page,pageSize,hasNext}` | 后台列表、我的文章、通知、订单、流水 |
| 游标分页 | `cursor`（首页不传）、`size`（默认 20，最大 50） | `CursorPage{list,nextCursor,hasNext}` | 信息流、评论、留言、我的点赞/收藏、AI 消息、搜索 |

- 参数越界（`page<1`、`pageSize>100` 等）→ 400，不静默纠正；`hasNext=false` 时 `nextCursor=null`。
- `cursor` 是不透明 Base64URL，原样回传，不要解析。

### 0.6 幂等与并发

- `POST /points/orders` **必带** `Idempotency-Key` 头（8~64 位可见 ASCII）：同键同体 → 200 + 原订单；缺失 → 400；同键不同体 → 409。
- **评论/留言没有幂等键保护**：docs/04 R056/R066 标"可选 Key"，但后端未实现该头（传了不生效，重复提交会发两条）。前端发评论/留言必须自行防抖（见附录 B-7）。
- 文章更新（PUT）**必带 `version`**（乐观锁）：冲突 409 `ARTICLE_VERSION_CONFLICT`，应提示刷新合并。

### 0.7 错误码速查

| HTTP | 典型 code | 前端动作 |
|---|---|---|
| 400 | `COMMON_VALIDATION_ERROR`、`*_INVALID` | 展示 data.errors 或 message |
| 401 | `AUTH_UNAUTHORIZED` / `AUTH_TOKEN_INVALID` / `AUTH_TOKEN_EXPIRED` | 引导登录 / 静默续期重放 |
| 403 | `AUTH_FORBIDDEN` / `AUTH_ACCOUNT_DISABLED` | 提示无权限，不要重试 |
| 404 | `*_NOT_FOUND` | **404 ≠ 接口错**（隐藏资源统一 404） |
| 409 | `*_CONFLICT` / `*_STATE_INVALID` / `ARTICLE_VERSION_CONFLICT` | 提示刷新后重试 |
| 410 | `*_EXPIRED` | 引导重新获取凭证 |
| 429 | `COMMON_RATE_LIMITED` / `AI_QUOTA_EXCEEDED` | 按 `Retry-After` 倒计时 |
| 503 | `AI_DISABLED` / `WECHAT_NOT_ENABLED` | 功能未开放 |

全量 105 个错误码见 **附录 A**；同一 code 只绑一个 HTTP。

### 0.8 SSE 约定

- 端点：`POST /ai/chat/stream`、`GET /notifications/stream`；`Content-Type: text/event-stream`。
- **必须 fetch + ReadableStream + Authorization 头**，禁用 EventSource、禁止 token 放 query。
- 帧格式 `event: <name>` + `data: <单行 JSON>`；每 15 秒 `: ping` 心跳。
- AI 五事件：`session` → (`tool` start/end)* → `delta`* → `done`；失败 `error` 收尾。通知流：`ready` → `notification`（带 `id:`，断线用 `Last-Event-ID` 续传）。实测样例见 §10/§16。
